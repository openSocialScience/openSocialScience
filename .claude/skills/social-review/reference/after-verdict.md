# 拿到判词之后

## ① 逐条核，不要照单全收

**审稿模型也会说错。**实测记录（`docs/design/PLAN.md` 九之四）里，
它对功效模块提了五条，四条半成立、有一条数值影响可忽略。

对每一条意见，先做三件事：

1. **回到原文对一遍**——它说的那句话真的是那么写的吗
2. **回到产出物对一遍**——它引的那个数真的是那个数吗
3. **判断是「错」还是「口味」**——错必须改，口味可以不改但要说明

## ①之二 反复改到收敛：停止条件用「且」不用「或」，轮次分文件

**借自 `auto-review-loop`**，它在自己的文档里注明早期版本用 `or` 是内部不一致：

```
可交付 = 最近一轮没有 FAIL/ERROR/BLOCKED  **且**  复审的审稿人不比首轮少
上限 = 2 轮。耗尽了可以导出，但论文要写明遗留了哪几条
```

**这两条别自己算——跑 `oss loop status`，第一行的「决定」就是答案（`review_first` / `continue` / `stop` / `export_with_open_items`），照做，不解释。**

每轮用 `--round N` 调审稿，报告存成独立文件（`review_..._r2.json`），
**上一轮的报告不覆盖**——它是「这条意见当时提过、后来怎么处理的」的唯一证据。

审稿人会给每条意见打 `[设计]` / `[数据]` / `[文字]`，第 2 轮起还有 `[新发现]`：

| 标签 | 怎么处理 |
|---|---|
| `[文字]` | 改 `paper.md`，重渲染 |
| `[数据]` | 能补就补；补不了写进局限 |
| `[设计]` | **能改设计就改**（回 `plan.json`、重跑、重画、改稿）；改不了、或改了会变成另一个问题，**写进论文的 Open questions 一节**，说明为什么不改；**试探性的规格（「加个控制变量看看」）走 `oss run --explore --for review-rN`，不要自己写回归——那些数字没有出处，`paper check` 会拦** |
| `[新发现]` | 本轮才提出的新观察，**不作为 FAIL 依据**，不计入遗留；记下，不改设计——值得做就写进论文的 Open questions |

设计级意见**不要求清零**——目标是合格，不是完美。要求的是**每一条都有交代**：
改了、写进去了、还是不同意（说理由）。工具会数：`oss loop status --run <运行目录>`。

**FAIL 必须复审一次。**判 FAIL 的多半是「话说过头」（关联说成因果、不显著说成没效应），
改字就能修，修完 `--round 2` 再审。两轮之后看 `oss loop status` 第一行的决定：`export_with_open_items` → 导出，遗留写进论文 Open questions；**不问用户，不审第三轮**（`oss review --round 3` 会被拒绝；确需加审用 `--extra-round --why "<理由>"`，留痕）。

**后端不可用时立即停，不算一轮。**

## 第二轮起：只判「处置了没有」

`--round 2` 之后，审稿人拿到的是上一轮的逐条意见，逐条判 `处置了` / `写进局限了` / `没交代`。
**只有「没交代」能构成 FAIL。**这一轮新看到的问题写在「新发现（不作为 FAIL 依据）」一段里，
每条以 `[新发现]` 开头——工具按这个标记把它们排除在遗留的设计级意见之外，
**本轮不要求解决**，值得做就写进论文的 Open questions。

## ② 改稿之后必须重跑校验

```bash
oss paper check  --run <运行目录>
oss paper render --run <运行目录>
```

**别只改渲染稿。**改 `paper.md`（带占位符的源稿），再渲染。
改渲染稿等于手打数字，下次渲染会被覆盖。

## ③ 判词与逐条意见要留在运行目录里

`review_paper_rendered.json` 不要删。**它是这篇稿子被审过的唯一证据**，
也是下次改稿时的对照。
