# 桌审 → 三位互盲审稿人 → 编辑综合

**结构借自 AERS 的 referee-sim，执行仍是我们的契约**：每一位都是审稿模型开的全新线程，
互相看不到对方的报告。三位不是「三个人格」，是**三种成见**——各自只盯一件事。

## 0 · 桌审（十分钟的编辑）

```bash
oss review --desk --run <目录>            # quick 档，只看成稿
```

十条：贡献一句话说得清吗、问题和设计对得上吗、识别策略有名字吗、有表吗、
正文有没有过程痕迹、话有没有超出设计、文献引了两边吗、局限是局限还是免责声明、
摘要有数字吗、能读吗。**FAIL 就先改再送审**——真编辑不会把会被桌拒的稿子送出去。
桌审报告叫 `review_desk.json`，**不算审稿轮次里的一位**。

## 1 · 三位互盲审稿人，各带一种成见

```bash
oss review --paper --level deep --run <目录> --round 1 --emphasis "识别策略与因果表述：结论有没有超出设计支持的范围、话跟数对不对"
oss review --alternatives --level deep --run <目录> --round 1
oss review --paper --level deep --run <目录> --round 1 --emphasis "局限与稳健性：该写的写全没有（含因果审计 review_plan.json 的每一条）、稳健性是不是事后补的"
```

| 位 | 成见 | 只盯 |
|---|---|---|
| 识别 | 「这不是因果」 | 结论超没超出设计、方向说反没有、显著说成证明没有；研究类型不是因果时，逐条判材料里 `causal_flags.json` 标出的说法越界没有（三位都拿到这份材料；识别审稿人逐条判，另两位看到越界的也点名） |
| **替代解释** | 「还能被别的解释」 | **主要结果还能被什么解释**——对着各批效应和**成员名单**看：效应最极端的那几批是不是同一类单位、同一段历史；同期冲击、口径变化、样本进出、反向因果、调节变量是别的东西的代理。**每条附一个手头数据能做的检查**（`sample_filter` / 控制 / 地区×年份固定效应 / 安慰剂） |
| 局限 | 「该写的没写」 | 功效（描述类是精度）、诊断、语料缺口、审计每条、代理变量，逐条对 |

`plan.json` 的 `research_type` 是 `measurement`、或 `also` 里有 `measurement`（新量表、新代理变量）时再加第四位：
`--emphasis "测量与数据：构念、代理变量、缺失机制、样本构成"`。

这一位另有**三问**，**全是门判不了的那一半**——门只核「声明了什么、产出在不在」，读不了论证：

| 问 | 判什么 | 对着什么看 |
|---|---|---|
| **构念与理论对不对得上** | 量表题目量的是不是作者声称的那个东西。`plan.measurement.construct` 是一句自由文本，程序核不了它写得对不对 | 题目原文（`indicators` 那几列的标签）、`binding.json` 的代理差距三栏、理论那一节 |
| **效度证据够不够支撑主张** | **报了一类证据，就只能说那一类的话**。报了效标关联却说「结构效度良好」，报了信度却说「这套测量站得住」——都是越界 | `plan.measurement.validity_evidence` 与 `evidence_outputs` 各登记了哪几类，正文实际说到哪一步 |
| **跨组比较的等价检验结论有没有被正确使用** | **部分等价只能比均值差、不能比潜变量水平**。载荷等价（弱等价）成立、截距不等价时，组间的平均分差里混着「题目在两组含义不同」，那个差不能读作构念水平之差 | `evidence_outputs` 的 `equivalence` 那份产出的实际结论，跟正文里对组间差的说法 |

前两问在任何一篇测量论文上都问；第三问只在有跨组比较时问（`groups_compared` 非空，或正文在比组）。

验收跑的教训：效应最负的三批（1994、2002、2004）几乎必然是后共产主义国家，
预期寿命断崖跟信息成本毫无关系——**论文手里有全部证据（批次表），却没人专门找这个故事**。
替代解释审稿人就是那个专门找的人；它给的检查直接进 `plan.json` 的稳健性，重跑。

每次调用都是**全新线程**，所以互盲是真的成立的。报告分别落盘，互不覆盖。

## 2 · 编辑综合（三份都冻结之后）

```bash
oss review --editor --round 1 --run <目录>
```

它读本轮全部报告，**不另起炉灶**：去重（几位都提的分量更重）、排序（必须改 → 应该改 → 可选）、
**裁分歧**（一位说加控制、一位说那是坏控制——明说怎么裁）、核对稿子（审稿人说没写而其实写了的）。
产出 `review_editor.json`，是一封决定信；**按它的顺序改，一次一条**，设计级的走 `oss route`。
综合不算审稿人；轮次的收敛仍按三位的判词算（`oss loop status`）。

**互盲的纪律，一条都不能省：**

| 规矩 | 为什么 |
|---|---|
| 每人只拿到**同一份不可变材料 + 自己的侧重** | 给了别人的意见就不是独立了 |
| **不给**别人的报告、不给共享的问题清单、不给草稿综合 | 同上 |
| 侧重是**工作透镜，不是审稿人身份/专业/履历** | 编一个「张教授，计量经济学家」是在演戏，不是在审稿 |
| **每份报告先冻结，再比较** | 先比较再定稿等于让后写的迁就先写的 |
| **重复和分歧都是独立性的证据，不许编辑掉** | 为了「显得多样」而改报告，就把独立性做没了 |
| 做不到隔离就**明说无法保证互盲** | 在共享上下文里生成三份，然后称之为独立评议，是假的 |

综合只能在三份都冻结**之后**做，而且是**另一份产物**，不是改动原报告。

**必须用 `--paper`，不要只传 `paper_rendered.md`。**
只把稿子交出去，最要紧的两个问题就核不了：

- 「稳健性是不是事后补的」——要对着 `plan.json` 里**事前锁定**的清单看
- 「局限写全没有」——要对着 `power.json` 与 `literature.json` 的 `notes` 看

多文件是**机械拼接原文**，不做摘要。**一总结就带上了你的口径**，
而这一步存在的全部意义就是拿到一个不带你口径的判断。
