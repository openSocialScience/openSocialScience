# 环节 4 · 检验做不做得了

> **这一环瘦身过**（idea 重构设计稿第七节）：候选的**经验预检**已经在环节 3 跑完并参与了重排——
> 构念绑不绑得上、最小可测效应多大，那里都看过了。这里做的是**对选中那一道题的深度检验**：
> 代理差距三栏、按文献效应量的功效判词、描述类的精度判词。**不要把环节 3 的预检再跑一遍当成本环的工作**。

## 输入
- `<运行目录>/ideas.json` 里选定的 `<idea_id>`、`profile.json`
- 环节 3 留下的 `prescreen_<idea_id>.json`（预检的数，用来跟本环的正式判词对照）
- 文献报告的效应量（有的话）
- `run_state.stage == "4-feasibility"`

## 产出
- `<运行目录>/binding.json`（代理 / 构造变量的**代理差距三栏**由你填：`construct_def` / `measures` / `gap`）
- `<运行目录>/power.json`

## 完成条件（全部满足才进环节 5）
- `binding.json` 的 `core_ok` 为 true（false 说明 treatment 或 outcome 绑不上，这个 idea 做不了）
- `status` 为 `proxy` / `derived` 的每一条，三栏都填全（`gap` 要写清偏向哪边、跟处理或调节变量相不相关）
- `power.verdict` 是 `pass` 或 `gray`；`gray` 的话把"功效落在灰区、对多大的效应才够"记下来，环节 7 写进局限。**描述类按精度判**：`fail` 是精度不足，**不停**，照样进环节 5（见下文「描述类题目按精度判」）
- **测量类不算功效**：判「证据做不做得出来」三条，过得了就落盘（判词恒为 `pass`、`mode` 是 `evidence`），过不了当场停（见下文「测量类题目判「证据做不做得出来」」）
- **仿真类也不算功效**：判「这个模型跑得出可判的东西吗」三条，**三条都只警告、不停**（判词恒为 `pass`、`mode` 是 `readiness`；见下文「仿真类题目判「跑得出可判的东西吗」」）
- `run_state.stage` 推进为 `5-plan`

## 禁止
- 带着 `power.verdict == "fail"` 往下写——`oss paper check` 会拒绝（这条管按功效判的研究；描述类的精度不足不停，处置了 `precision_low` 就能往下写，见下文）
- 把功效 FAIL 当成可报告的结果（它是设计层面的失败）
- 三栏差距大到"理论和测量对不上"还写进局限了事——回环节 3 去搜更好的列
- 叫用户来裁决灰区（灰区的产出只是那一句话怎么写）
- 事后再算功效：**功效是事前的**，`oss eval` 会核先后

## 命令
```bash
oss bind  --run <运行目录> --idea <idea_id>
oss power --run <运行目录> --idea <idea_id> \
          --effect <文献报告的效应量> \
          --effect-source "<哪条语料记录、哪一页、原话>"
```

**`--effect-source` 不是可选的礼节。**整个功效判词建立在效应量这一个数上，
而链上别的数都能追回结果文件，唯独它是从文献里搬来的。**不给出处就判不了 `pass`**
（封顶灰区），论文里也**不许写「按文献报告的效应量」**——那是一句无法核对的话。

出处要能核：写清是语料里哪条记录、哪张表或哪一页、原话是什么。例：

```
--effect-source "W2411634914（Fort 等 2016）表 3，英格兰组 d ≈ 0.12"
```

**语料里翻不到可用的效应量就照实说**：`--effect-source "语料里没有可比的效应量，
0.2 是社科常见的小效应约定值（Cohen 1988），属假定"`——这样判词封顶灰区、
局限里写清楚，也比冒充文献值强。

**功效按有效样本量算，不按行数算**：有效样本量 = 行数 ÷（整群设计效应 × 权重设计效应（Kish）），
`oss power` 自动按画像的权重列折，`power.json` 里两个设计效应分开报。
加权的调查数据功效会比按行数算的低——**这是真的，不是工具的错**：权重越不均，同样的行数含的信息越少。

## 功效判词与出路

**这一节只管按功效判、估一个效应的研究（因果，以及没写研究类型的老题）。**描述类按精度判、`fail` 不停，见下一节；
测量类既不算功效也不算精度，判「证据做不做得出来」，见再下一节；仿真类判「跑得出可判的东西吗」，见最后一节。

| 判词 | 怎么办 |
|---|---|
| `pass` | 往下走 |
| **`gray`** | 往下走，**写进局限**：功效落在灰区、对多大的效应才够 |
| **`fail`** | **停。这个结局/样本测不出目标效应。**不许带着 FAIL 往下写——`oss paper check` 会拒绝。**这条只关功效，审计 FAIL 另有规矩（环节 7.5）** |

`fail` 的三条出路，选一条：换结局 / 换样本扩窗口 / **换题目**——**这一条要用户点头**（见环节 7.5）。
只有文献里有明确更大的效应量时才有第四条：`oss power --effect <值>` 重算，出处写进论文。

## 描述类题目按精度判

描述研究回答「是什么」（水平、分布、组间差、趋势），不是测一个效应——按功效判会把它误停。
**`oss power` 按选中题目的研究类型自动分路**：`research_type` 是 `descriptive` 的（运行目录已有 `plan.json` 就看计划的，
否则看 `ideas.json` 里那一条）不算功效、改算**精度**，`power.json` 的 `mode` 写 `precision`。命令还是同一条：

```bash
oss power --run <运行目录> --idea <idea_id> \
          --effect <有意义的最小差别，标准差为单位> \
          --effect-source "<这个差别凭什么算有意义：出处或理由>" \
          --group-col <分组列，逗号分隔，至多两列>
```

- **`--effect` 在描述类里是有意义的最小差别**（标准差为单位），**不打发表偏倚的折**——那个折是给文献里搬来的效应量打的
  （发表出来的偏大），有意义的差别是你定的门槛，不是估计值
- **`--effect-source` 照旧必填**：没有出处也没有理由，判词封顶灰区。环节 5 计划里的 `description.meaningful_difference`
  是同一个差别写给论文与审稿看的版本（带单位与出处），不参与计算
- **`--group-col`**：不给（也还没有本题的计划），主要比较是总体水平；给了，主要比较是排序第二类对参照组（排序第一类）之差——跟 describe 的主结果同一对比；
  要换参照组就在 prep.py 重编码。**最小分组单独报**
  （`power.json` 的 `min_cell_label`、`min_cell_n_eff`）。最小分组太小的，分析之后 `oss route` 还会开 `small_cells`
- **有了本题的计划（`estimator: describe`），主要比较按它的 `description.kind` 定**：`gap` 是上面那对组差，就是 describe 的主结果；
  `level`、`distribution` 的主结果是全样本均值，**按总体水平判**，分组只用来报最小分组；`trend` 按首两期之差近似（判词写明是近似）。
  计划是描述类、估计量不是 describe（因果降为描述的 `ols_fe` 这类）又没给 `--group-col` 的，treatment 二值就按它的两组之差算——
  这也是分组，同样不能跟 `--n` 一起用；treatment 不是二值的（连续变量），按总体水平算，判词读作标准化系数的精度：
  X 每变一个标准差，Y 变多少个标准差
- **有了本题的计划，分组、整群、权重没给的按计划取**：分组列取 describe 的 `description.groups`（趋势再加 `over`），
  整群列取 `survey.psu`（没写取 `cluster_level`），权重取 `weights`（空着就是不加权，画像检出的权重列也不用）；
  给了的照给的。按计划取了哪几样，警告与判词里各说一次
- 精度跟功效同一口径，**按有效样本量算**；报的是主要比较的 95% 区间半宽（`precision_halfwidth`，标准差为单位）。
  精度也是**事前的**：同一条 `oss power`，`oss eval` 照样核先后
- **只数分析真会用到的行**：有了本题的计划，就是 `oss run` 用的那批行（样本筛选；结局、分组或处理与控制、权重与抽样设计列
  去缺失）——`oss run` 会拒的（比如权重有 0），精度也拒，理由照抄；还没有计划，先去掉结局缺失、权重缺失或不为正、
  簇列或分组列缺失的行。去掉多少行、为什么，判词里写。按子样本算就在 prep.py 里筛好或写进 `sample_filter`——
  `--n` 不跟分组一起用（按计划取的分组也算）
- **`--effect-metric raw`：差别按结局原单位给**。`--effect` 缺省按标准差单位读，结局是比例时最容易写错：想说
  「差 5 个百分点」写成 `--effect 0.05`，会被读成 0.05 个标准差（比例在 0.3 上下时，5 个百分点约是 0.1 个标准差），
  判词就严了一倍。加 `--effect-metric raw`，工具按结局的（加权）标准差折算，判词里两种单位都写（见下例）；按功效判的题不认 `raw`
- **`--cluster-col <簇列>`**：不给、本题的计划也没写 `survey.psu` 或 `cluster_level`，就不算整群（当每人独立抽样，精度偏乐观）；
  给了按它数簇，组差的 ρx 也从数据算

```bash
# 结局是 0/1 的比例，差 5 个百分点算有意义
oss power --run <运行目录> --idea <idea_id> --effect 0.05 --effect-metric raw \
          --effect-source "<5 个百分点凭什么算有意义>" --group-col <分组列> --cluster-col <簇列>
```

| 判词 | 怎么办 |
|---|---|
| `pass`（够：区间半宽明显窄于有意义的最小差别） | 往下走 |
| **`gray`**（灰区：跟它差不多宽） | 往下走，**写进局限**：精度落在灰区、分得出多大的差别 |
| **`fail`**（精度不足：比它还宽） | **不停，往下走。**环节 6 的 `oss route` 开 must 级、可处置的 `precision_low`，二选一：**收窄题目**（合并分组、只报总体层面），或**局限写明这份数据分不出小于多少的差别**——`oss route --disclose precision_low --why "<选了哪条、写在哪>" --run <运行目录>`。没处置，`oss paper check` 照样拦 |

两道倍数以 `power.json` 的 `gray_band` 为准。**精度不足不停**：描述研究「分不出差别」本身是结果，零结果照样该写成论文；
功效不足就停的规矩是给测一个效应的研究定的。

## 测量类题目判「证据做不做得出来」

测量研究问的是「凭什么说这几道题量的是那个东西」，**可行性不是样本量问题**，是手头的数据支不支持你要给的那种效度证据。
`oss power` 按研究类型自动分路：`research_type` 是 `measurement` 的，**功效那一路整条关掉**——不算效应量、不打发表偏倚的折、
不算最小可测效应、不出功效判词，`--effect` 与 `--effect-source` 在这一路上都不读，`power.json` 的 `mode` 写 `evidence`。

```bash
oss power --run <运行目录> --idea <idea_id>
```

判三条，都从计划的测量块（`plan.measurement`）与数据算：

| 判什么 | 什么条件下响 | 级别 |
|---|---|---|
| **题目数够不够** | `kind: instrument` 且 `indicators` 少于 3 道 | **停**（退出码 1，编号 `plan.measurement.too_few_indicators`） |
| **跨组比较有没有分组变量** | `groups_compared` 里的列不在数据里、整列缺失、或只有一个取值 | **停**（`plan.measurement.group_missing`） |
| **有没有可对账的外部指标** | `kind: instrument` 且声明了 `criterion`，而数据里除这几道题之外一列可用的都没有 | 警告 + 处方（`plan.measurement.no_criterion_var`），**不停** |

- **两道题的量表给不出结构效度**：两个指标的因子模型识别不了（自由度为负），做不出因子结构，剩下的只是一个相关系数。
  样本量再大也补不上——至少三道，或者改成用现成量表做实质研究（`kind: application`）
- **外部指标那条不停**：效标常要另找一份数据（`oss data search` 找、`oss merge` 拼），停在这里等于不许做。
  两条出路：合并一份带外部指标的数据再声明 `criterion`，
  或把 `criterion` 从 `validity_evidence` 里去掉，只报这份数据做得出来的那几类，论文里也只说那几类的话
- **测量块还没写就跑，三条一条都核不了**——那不是「过了」，是「还没判」，`oss power` 会把这句写进警告与判词。
  测量类的正常顺序是**先写好 `plan.json` 的测量块（环节 5 的写法），再回来跑 `oss power`**；先跑了的，写完计划重跑一次
- **主类型不是测量、但计划里写了测量块的**（典型：先自建指数再估影响——主类型 `causal`、`also` 里写 `measurement`），
  **这三条照样核**：主类型那一路一行不动（该算功效还是算功效、该判精度还是判精度），只多加测量那类的检查，
  判词那一行末尾多一句「附带的测量部分：……」。**判据看的是测量块在不在，不是 `research_type` 或 `also` 怎么写**——
  写了块就得对得上，少填哪一栏都躲不掉。声明了附带测量却没写块的，这三条核不了，说一声、不停（拒是环节 5 计划门的事）

**环节 4 之后研究类型变了**（计划从因果降为描述，或写成了别的类型），**或者换了题**（`oss anchor switch`），都要重跑
`oss power --idea <计划的 idea_id>`（会按计划的分组、整群与权重算）——不然环节 6 的 `oss route` 开 must 级、驳回不了的
`power_mode_mismatch`：那份报告答的不是这篇论文的问题。换了题、报告已经按新题算过而计划还是换题前那道题的，这一条说先给新题写计划。

## 仿真类题目判「跑得出可判的东西吗」

仿真研究的可行性**根本不是样本量问题**——想跑多少个小人就跑多少个，跑十万个也不会让
结论更可信。真正的可行性是**跑出来的东西够不够分辨条件之间的差别**。`oss power` 对
`research_type: simulation` 走第四支：功效那一路整条关掉（不算效应量、不打发表偏倚的折、
不算最小可测效应、不出功效判词，`--effect` 与 `--effect-source` 都不读），`power.json`
的 `mode` 写 `readiness`。

```bash
oss power --run <运行目录> --idea <idea_id>
```

判三条，**都从入库档案（`sim_state.json`）与计划的仿真块算，一条都不重算**：

| 判什么 | 什么条件下响 | 级别 |
|---|---|---|
| **条件够不够** | 配料单 `conditions` 只有一个条件 | 警告 + 处方（`plan.simulation.single_condition`），**不停** |
| **重复够不够** | 某条件 `n_reps` < 3 | 警告 + 处方（`plan.simulation.low_reps`），**不停** |
| **对照物在不在** | `stands_in_for_humans` 为真，而 `real_benchmark.data` 指的那份数据不在 | 警告 + 处方（`plan.simulation.no_benchmark`），**不停** |

- **三条都只警告、不停**，跟测量类不同：两道题的量表在数学上就给不出结构效度，所以那边停；
  而**单条件与重复不足都是正当研究**，正确答案是把话说软，不是不许做。
  单条件只能做模式展示、不能做条件间比较；重复不足全文降级为「初步 / 探索性」
- **还没入库就跑**（环节 4 常常在花钱跑模拟之前）：三条一条都核不了，`oss power` 会把
  这句写进警告与判词。**那不是「过了」，是「还没判」**——跑完模拟 `oss sim import`
  之后重跑一次
- **入库档案会过期**：货箱改过配料单、或者重跑过模拟而没重新入库，三条判的就是入库
  那一刻的货箱。`oss power` 会拿货箱现在的 `sim.meta.json` 对一遍，对不上就说一声
  （`plan.simulation.state_stale`）——重新 `oss sim import` 即可

**跟真实调查对账的那两条（方差比、关系方向）不在这一步**：那要同时拿到合成数据与真实
数据，是环节 6 `oss run` 才算得出来的，见环节 5 的仿真块写法。
