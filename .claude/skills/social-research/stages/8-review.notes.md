# 环节 8 的散文：四个标签、对着锚点看、改稿改哪一份

它先桌审（`--desk`），再跑三位互盲审稿人（识别 / **替代解释** / 局限），最后编辑综合（`--editor`）。
**每条意见都带类别标签**，由审稿人打，工具计数：

| 标签 | 意思 | 你怎么处理 |
|---|---|---|
| `[文字]` | 改措辞、补说明、补局限 | 改 `paper.md`，重渲染 |
| `[数据]` | 要补数据或重构变量 | 能补就补，补不了写进局限并说明 |
| **`[设计]`** | 换估计量、换样本、换对照、补检验、换识别策略 | **能改就改**（回 `plan.json` → `oss run` → 重画图 → 改稿）；改不了就写进论文的 Open questions 一节（局限之后），说明为什么；**想先试一试不要自己写 python，走 `oss run --explore --for review-rN`（见环节 6）** |
| `[新发现]` | 第 2 轮起才提出的新观察 | **不作为 FAIL 依据**，不计入遗留；记下、不改设计，值得做就写进 Open questions |

没打标签的意见工具按 `[设计]` 算——判不了就按最严重的算；第 2 轮起写成 `[设计] N 处置了 / 写进局限了` 的不算遗留。

（循环规则与决定表见 ../rules/stop-conditions.md）

**迭代设计时对着锚点看**——`run_state.json` 的 `anchor` 里冻着原始方向和选定的 idea（`loop_state.json` 里那个 anchor 是按**当前**的 plan/ideas 重算的，对着它看不出漂移）。
换设计是为了回答**同一个问题**，不是换一个能通过的问题。

改稿要改 `paper.md`（带占位符的源稿）再重新渲染，**不要改渲染稿**——
那等于手打数字，下次渲染会被覆盖。
