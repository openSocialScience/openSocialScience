# 环节 1 · 数据画像

## 输入
- 用户给的数据文件，或数据包 `pack:<名>`，或两者都有
- `run_state.json` 不存在，或 `run_state.stage == "1-profile"`

## 产出
- `<运行目录>/profile.json`（多份数据先拼再画像：**横着拼**用 `oss merge` 出 `merged.csv`、
  **竖着摞**用 `oss stack` 出 `stacked.csv`；宽表先 `oss reshape` 出 `long.csv`）
- `<运行目录>/prep.py`（构造了变量才有；**每个构造式一段注释写依据**）
- `fig_structure`、`fig_missing`、`fig_clusters` 三张诊断图

## 取列：这一步会悄悄替后面出题

数据包动辄上千列（V-Dem v15 有 1818 列），取哪几列进运行目录是你定的。
**取列出题**是四条不变量都防不住的一个洞——它发生在出题之前，不在它们的管辖范围里。

真跑 r20260916_netdem 的教训：只取了 6 列，于是环节 3 把「网络自由度」写成
「本数据没有」，而 `v2mecenefi`（政府互联网审查力度）本来就在包里。

两条规矩：

- **按用户的研究方向取，宁宽勿窄。**方向里出现的每个概念都换两三种叫法搜一轮
  （`oss data columns <包名> --search "叫法1, 叫法2"`），够得着的都取进来。
  多取几列的代价是画像慢一点；少取的代价是一整类题在环节 3 被误判成「做不了」
- **取了哪些、为什么、什么搜了没搜着，留痕**：

```bash
oss trace save --step data_notes --note "取列：<列名清单>；按方向的 <概念> 搜过 <叫法>，<没搜着的> 包里确实没有" --run <运行目录>
```

没有这条留痕，事后就分不清「这份数据真没有」和「我当时没取」——
而环节 3 的清单乙会把两者写成同一句话。

## 完成条件（全部满足才进环节 2）
- `profile.json` 存在，且已读过 `structure.kind`、`structure.nesting_levels`、各列 `within_variation`
- 多份数据已由 `oss merge` 拼过；丢超一成时用 `--allow-loss <值>` 显式接受，并把这个数字与"丢掉的那批系统性地不同"记下来，环节 7 写进局限
- **多轮调查（CGSS/CFPS/GSS 的若干轮）已由 `oss stack` 摞过**——写一份映射文件
  （`oss schema stack` 看格式），逐轮说明哪一列对应哪个概念。**不许自己在 `prep.py` 里
  `pd.concat`**：那一段是全链唯一没人核的计算，而多轮调查最贵的三个坑全在这儿——
  编码翻转（同一道是非题改版后 `1=是` 变成 `4=是`）、逐轮改名（同一个问题每轮列名都不同，还可能换大小写）、
  某一轮整个模块没问。`oss stack` 查出编码翻转会**拒绝执行**，直到你显式声明怎么对齐
- `oss stack` 报的每条 ⚠ 与 ○ 都要读：「整轮缺席」意味着那一轮**根本没问**（不是缺失）；
  「缺失码逐轮不同」意味着摞成一张表之后**再想按轮次分别处理就晚了**，要在写 `prep.py` 时一起处理
- 画像判 `cross_section` 但实为每人一行、各轮变量并排的，已 `oss reshape` 转长表并对长表重新画像
- 三张诊断图都画了、都看过；`oss reshape` 输出里"是猜的 / 不是每轮都有 / 不随时间变"三句都读过
- 撑不起用户方向的地方**现在就说**，不要往下走二十步再说
- `profile.json` 的 `suspected_missing_codes` 非空时（疑似缺失值代码：99=拒答、-99=缺失这类），
  **按把握分两路走，不要混成一路**：
  - **`labeled_missing_codes` 里的**——文件的取值标签原文就写着「不适用」「拒绝回答」，
    **这不是推断，不用问**，照着在 `prep.py` 里改成缺失即可（构造式照旧一段注释写依据）。
    CGSS2017 单轮 786 列里有 472 列属于这一类，逐列问是问不完的
  - **不在其中的**（没有标签可依、按分布猜出来的）——**停下来逐列问用户是不是**，
    是就改，不是就记一句。**不许自己决定**：抹错一列是把真数据当垃圾扔，
    不抹是把垃圾当真数据算，两头都错得很安静
- 改之前**先算一遍剔除后的均值，跟画像里的对一下**。CGSS2017 的个人年收入
  带着 9999997/8/9 三个码，画像报的均值是 **58 万元**，剔掉之后是 **4.1 万**——
  差 14 倍，而且全程不报任何错
- **跳问造成的 0 不是缺失值代码，探测器抓不到它**（真调查数据上量过：某一题一万两千人里
  一万一千个 0，那是"上一题答了否、这题跳过去了"，不是真的答了 0）。
  连续变量的均值明显不合常理时，去码本里查这一题的跳问规则，别当成真值算
- `profile.json` 的 `survey.likely` 为真时（画像认出了权重、分层、初级抽样单位、插补标记里的任何一样），
  `survey` 里的候选（`weight_candidates` / `strata_candidates` / `psu_candidates`）**都是疑似，不是答案**。
  画像只会按名字和形态猜：名字里没有任何线索的设计变量（比如编号式的列名 `s41`），画像根本认不出来；
  横截面权重与面板权重常同时在，该用哪个也看不出来：
  - 用户说了是哪份调查（「这是 CGSS 2017」），用 `oss data info <包>` 调出登记的抽样设计
    （分层、初级抽样单位、逐年权重、出处）；写着「待核」的格**问用户或查码本，不许猜**——
    跟引用不许编是同一条规矩
  - `imputation_flags` 里的每个插补标记列，记下它标的是哪一列（画像认不出的那一格是空串，去码本里查）
  - 确认下来的设计在环节 5 写进 `plan.survey`
- 数据来自仿真货箱时，`sim_state.json` 已在运行目录里，且 `downgrade` 字段已经读过并原文逐字念给用户
- `run_state.stage` 推进为 `2-literature`

## 禁止
- 自己写拼接脚本、重塑脚本（见 `../rules/explore.md`）
- 要申请的数据集拿不到时拿别的数据顶替——原样转告申请办法然后停
- 替工具认定"Korea 是韩国还是朝鲜"：候选是给你看的，不是答案
- 六千列的调查文件不挑列就整份读
- `cd` 进运行目录（两次事故：产出落进 `runs/xxx/runs/xxx/`）
- 让 `oss reshape` 顺手做量表反向、取对数、转哑变量——那些是你的判断，写进 `prep.py`
- 绕过 `oss sim check` 直接拿箱内 CSV 当普通数据用——sim: 来路的数据必须先验货（见上方「数据来自仿真货箱」一节）

## 命令
```bash
oss data list                                   # 有哪些、哪些已在本机、哪些要申请
oss data info <名>
oss data get <名> [--columns a,b,c] [--out <运行目录>/x.csv] --run <运行目录>   # 第一次下载、转 CSV、记出处；之后用缓存
oss data get gss --columns year,id,wtssall,educ,paeduc --out <运行目录>/gss.csv --run <运行目录>
oss profile <数据文件> --run <运行目录>
oss merge <主数据> <要拼进来的> --on country,year [--map crosswalk.csv] [--allow-loss 0.13] --run <运行目录>
oss schema stack                                # 映射文件怎么写
oss stack <映射文件.json> --run <运行目录>        # 多轮调查竖着摞成一张
oss reshape <数据文件> --run <运行目录>
oss figure structure --run <运行目录>
oss figure missing --run <运行目录>
oss figure clusters --run <运行目录> --cluster-col <列名>
```

## 数据来自仿真货箱（`sim:`）时

`--- data: sim:<箱目录>` 给的不是数据文件，是一只**待验货**的仿真货箱——顺序
不能倒，验货前不许碰箱子里的 CSV：

1. **先验货**：`oss sim check <箱目录>`。拒收（problems 非空）就停——把
   problems 原样转给用户，不许绕过 check 直接翻箱子拿 CSV 当数据用（这条
   也写进本环节「禁止」一节）
2. **入库分两条路，按箱子怎么来的分叉**：
   - 箱子是 `/social-sim` 跑出来的、收尾报告已经给了运行目录 → **沿用那个
     运行目录**（就是报告里写的那个 `<运行目录>`），不要新建；这种情况下
     `sim_state.json` 已经在那个目录里了，**不用再 `import` 一次**——
     `check` 这一步仍然要跑，验货不因为已经交接过而豁免
   - 箱子是手工装的（或没收到收尾报告给的运行目录）→ 照旧自建运行目录，
     验货通过（含只带警告的通过）才能入库：`oss sim import <箱目录>
     --run <运行目录>`
   - 拿不准走哪条（用户只递了箱路径、没提收尾报告）→ 先问用户一句：有没有
     `/social-sim` 给的运行目录？有就沿用，没有才自建——问这一句，省得平白
     多建一个孤儿目录
3. 数据文件就是 `<箱目录>/states.csv`——喂给 `oss profile` 画像；`events.csv`
   留给要做机制型分析（谁影响了谁、扩散路径）的场合选用，画像这一步不必碰它
4. 读一遍 `<运行目录>/sim_state.json`：`downgrade`、`single_condition`、
   `warnings` 三个字段的内容**原文逐字念给用户，不许改写**——跟
   `/social-sim` 验货时的规矩同一个强度，不是读过就算数；`downgrade` 为
   `true` 时要当场记下来，环节 7 写论文局限时这一条不能漏（`downgrade=true`
   意味着论文只能作「初步/探索性」表述）
5. `states.csv` 的个体是 **condition×rep×agent_id 复合体**——`agent_id` 跨场重复编号，
   A/1 的 0 号小人与 B/1 的 0 号小人是两个不同的模拟人，不是同一个体跨场被追踪。
   画像判出 `structure.kind == "repeated_cross_section"`、`unit_id` 为空，
   是**预期现象，不是数据坏**（画像的 `detection_note` 会说「没有个体标识」
   ——**别信以为真去修数据**）。做面板/DID 之类需要个体标识的分析前，
   在 `prep.py` 里拼一列复合 `unit`（每个构造式一段注释写依据——本环节既有规矩），
   环节 5 的 `plan.unit` 用这一列。V0 真跑就是这么处理的
