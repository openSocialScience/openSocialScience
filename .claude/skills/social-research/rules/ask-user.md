# 什么时候可以问用户

| 可以问 | 不许问 |
|---|---|
| 没给数据 | 设计站不站得住 |
| 数据包要申请、拿不到 | 要不要换题目（审计 FAIL 之后） |
| 输入里设了 `checkpoint:` | 审稿意见改不改 |
| 审稿后端坏了（家族错 / 不可用） | 结论怎么写 |
| 功效 FAIL 后三条出路选哪条（描述类没有这一问，见下） |  |
| **整理稿确认**（带 `idea:` 时的 checkpoint `idea`，缺省开） |  |
| **自带想法时功效 FAIL 走到「换题目」那条出路** |  |
| **仿真整理稿确认**（`/social-sim` 缺省停一次） |  |
| **`oss sim doctor` ✗ 项处理不了** |  |
| **402／余额类断粮，全停告知用户去充值** |  |

**手册没列的情况，自己按手册决定，不问。**「这是重大决策」不是问的理由——重大决策手册已经替你做了。

**自带想法时，功效 FAIL 的第三条出路「换题目」等于停下来问用户。**
不带 `idea:` 时你还能在候选清单里挑另一个；自带想法模式下 `ideas.json` 里只有用户那一条，
「换题」没有别的题可换——只能把三条出路和你的判断一起交给用户，拿到一句同意再动。

**描述类没有功效 FAIL**：按精度判，精度不足不停、没有三条出路，按 `precision_low` 处置（见 [stop-conditions.md](stop-conditions.md)）——上表两行功效 FAIL 的问法对描述类都用不上。

## 三个 checkpoint 开关

### 可选：换设计前停下来让用户看一眼

输入里带 `--- checkpoint: design` 时，因果审计判 FAIL 之后、动 `plan.json` 之前**先停**：
把审计的逐条意见、你打算换的设计、还有**你没选的备选**（为什么不选）列给用户，等用户点头再改。
第一次走这个循环时，执行者自己选了「用处理前走势筛样本」——那是个有争议的选择，
当时如果有人在场很可能会拦。**最关键的判断，用户想在场就让他在场。**

### 可选：选题时停下来让用户看一眼

输入里带 `--- checkpoint: ideas` 时，陪审团砍完题**先停**，把保留的候选、
砍掉的理由、`needs_extra_data` 的那几个列给用户，等用户选了再继续。
没带这个参数就自己走。**顶刊论文里有一样东西系统给不了：领域专家的直觉——
这个开关就是让它进来的门。**

### 缺省开：自带想法的整理稿确认

带 `--- idea:` 时**缺省就停这一次**（checkpoint `idea`，**单数**，跟上面那个复数的
`ideas` 不是一回事）：把整理稿的九栏、研究类型、陪审团的三条意见、`needs_extra_data`
**一次性**回给用户，用户点头或改字，然后继续。**这是自带想法模式下唯一的一次停**。
（哪九栏，见 `social-idea/reference/tidy-mode.md` 第 3 步——那份文件是这九栏的唯一出处。）

用户写 `--- checkpoint: none` 才不停。**X 或 Y 在整理稿里留空的，必须在这一次补齐**
（决定 1：不要求用户按格式填，但确认时得补全）——非程序员写不出规范格式，
让你整理、用户点头，比要求用户填表靠谱。
