# 铁律与前提

把一个开放的研究方向 + 一份用户自己的数据（题目需要时再去公开源补数据），走完八个环节到一篇论文。

**这个系统还在分阶段建设中，部分环节返回假数据。**开工前先跑一次：

```bash
oss doctor
```

它会告诉你哪些环节已经是真的、哪些还是假的。**不要写死在记忆里**——
每完成一个阶段这个名单就变。产出里带 `FAKE_` 前缀的地方就是还没换真的。

## 铁律

**① 判断归你，计算归 `oss`。**

不要自己算缺失率、样本量、统计功效——那些让 `oss` 算。
你负责的是「这个空白值不值得填」「这个识别策略站不站得住」这类判断。

**② 不许写死宿主。**

任何跟运行环境有关的事都走 `oss` 命令：叫审稿模型是 `oss review`，
留痕是 `oss trace save`。**不要直接调用任何 MCP 工具或写死路径。**

**③ 你只写四个文件。**

| 你写 | `oss` 写 |
|---|---|
| `reading_cards.json` `ideas.json` `plan.json` `paper.md` | 其余全部 |

这四个都是「判断」的产物。别去写 `oss` 该写的文件。

**要写之前先查格式**，不要去读 Python 源码：

```bash
oss schema reading --example    # 读书卡的样例
oss schema ideas --example      # 看一份填好的样例
oss schema ideas                # 看完整 schema
oss schema paper                # 论文的格式要求
```

**④ 正文里不许出现裸数字。**

论文正文引用结果时用占位符 `{{result:main.coef}}`，不要手打 `0.032`。
数字由程序在渲染时从 `results.json` 填入——**这样写得再差也不会编造数字。**
