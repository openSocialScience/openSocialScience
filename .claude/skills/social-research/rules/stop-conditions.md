# 停止条件

**循环的规则：**

```
可交付 = 最近一轮没有 FAIL/ERROR/BLOCKED  **且**  复审的审稿人不比首轮少
上限 = 2 轮。耗尽了可以导出，但论文要写明遗留了哪几条
```

每轮审完跑 `oss loop status`，**第一行「决定」就是下一步，照做，不解释：**

```
  review_first            → 先审一轮
  continue                → 改稿、重渲染、用它给的 --round N 复审
  stop                    → 导出
  export_with_open_items  → 导出；遗留的设计级意见写进论文 Open questions；**不再复审、不问用户**
（oss review --round 3 会被拒绝；耗尽后**再开一轮**也会被拒绝——但**本轮少回来的那一位可以补齐**，重跑那一位的 --round 2 不算加轮；上限 2 轮是门，不是建议）
```

每轮结束跑一次，它会告诉你能不能交付、还差什么：

```bash
oss loop status --run <运行目录>      # 0 收敛或还没审过 / 3 还要复审 / 4 轮次耗尽——**判可交付看第一行的「决定」，不看退出码**
```

设计级意见**不要求清零**，要求**每条都有交代**。目标是合格，不是完美——
原来要求清零、三轮，一次跑 77 分钟花在审稿上。

**后端不可用（退出码 1）不算一轮，也不是通过。**`oss review` 遇到网关超时会自动降一档重试一次；
仍然失败就如实记「本轮未得到裁决」，不要拿上一轮的判词充数。

## 审计 FAIL、替代设计试过也穷尽之后，怎么走

```bash
oss trace save --step design_alternatives_exhausted --note "<每一种替代为什么都不可行>" --run <运行目录>
```

记了这条留痕之后：**保留原设计，全文降级为关联，审计的每条意见写进局限，继续往环节 7 走。**

「降级为关联」落到 `plan.json` 上，就是把 `research_type` 从 `causal` 改成 `descriptive`（别的字段不动）——`oss run` 与 `oss paper check` 认得这条理由（研究类型门），正文从此走描述类的措辞检查。**结果不显著不是降级的理由**，程序也不认它。穷尽之后计划还标因果的，`oss paper check` 与 `oss paper export` 也按已降级查措辞（明确的因果说法照拦）。

因平行趋势不成立而降级的，处方里的 `pretrend_fail` 照样要处置：`oss route --disclose pretrend_fail --why "<为什么解决不了，降级为关联>" --run <运行目录>`（理由写进局限）。

**不换题目、不换数据、不问用户**（带 `--- checkpoint: design` 的除外，见 [ask-user.md](ask-user.md)）。「宏观面板回答不了这个因果问题」是一个要写进论文的发现，不是换题的理由。
换题只出现在功效 FAIL 的三条出路里（环节 4）。**换题是用户的决定，不是你的**：还没跑过 `oss run`（锚点没冻结，`oss anchor switch` 会拒）的，把三条出路和你选哪条告诉用户，拿到一句同意再回 `ideas.json` 换；已经跑过分析的，只能 `oss anchor switch --to <idea_id> --why ... --authorized-by user`。

**自带想法（输入带 `--- idea:`）时这条更硬：连候选都没有。**`ideas.json` 里只有用户那一条
`idea_001`，「换题」不是从清单里挑另一个，而是**推翻用户交上来的题**——
只能由用户发起。你能做的是把情况说清楚（功效算出来多少、缺什么、三条出路各是什么代价），
然后停下来等。**判词不好看不是换题的理由**：陪审团说理论钩子弱、空结果没价值、缺数据，
都原样写进论文局限，那一条**不许删、不许改题**。

**「功效 FAIL 就停」对描述类不适用。**描述类（`research_type: descriptive`）在环节 4 按精度判，不按功效判：精度不足**不停**，
也没有上面那三条出路，按处方 `precision_low` 处置——收窄题目（合并分组、只报总体层面），或局限写明这份数据分不出小于多少的差别
（`oss route --disclose precision_low --why "<选了哪条>" --run <运行目录>`）。描述研究「分不出差别」本身是结果，**精度不足不是换题的理由**。

## 第二轮起：只判「处置了没有」

`--round 2` 之后，审稿人拿到的是上一轮的逐条意见，逐条判 `处置了` / `写进局限了` / `没交代`。
**只有「没交代」能构成 FAIL。**这一轮新看到的问题写在「新发现（不作为 FAIL 依据）」一段里，
每条以 `[新发现]` 开头——工具按这个标记把它们排除在遗留的设计级意见之外，
**本轮不要求解决**，值得做就写进论文的 Open questions。
