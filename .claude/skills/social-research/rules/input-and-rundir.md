# 参数怎么拆、数据怎么拿、运行目录的两条脾气

## 三种进来的方式，都要认

**用户不必学任何符号。**下面三种都是合法输入，认不出来是你的问题不是他的：

| 他打的 | 你做什么 |
|---|---|
| 什么都没打（只有 `/social-research`） | **直接进访谈**（见下），一样一样问 |
| 一句人话（「我想看教育扩张和生育率的关系，用 QoG，按社会学来」） | **自己理解**，然后**复述一行等他点头**，缺的再问 |
| 带 `---` 的完整写法 | 照下面机械拆，一个字不改 |

**带 `---` 就机械拆，不带就理解。**两条路的差别是可靠性：机械拆绝不会误读，
理解可能读错——所以理解那条**必须复述**。读错了他一眼看得见，改一个字的事；
不复述就闷头往下走，是跑了七十分钟才发现用错了数据。

复述一行就够：

> 方向「教育扩张与生育率」｜数据 QoG 数据包｜学科 社会学｜中文稿。对吗？

**建好运行目录后第一件事：把原始输入原样记下来。**

```bash
oss trace save --step input --note "<用户打进来的那一整串，一个字不改>" --run <运行目录>
```

**这是唯一独立于你自述的记录。**没有它，「用户到底带没带题」只能听你说——
而 WorkBuddy 那次的事故正是你自己认定「这算他带了题」，把整套出题流程跳过了。
`oss eval` 的 `byo-idea-declared` 查的就是这条留痕。

## 带 `---` 时怎么拆

用 `---` 分段：

```
数字化对城乡收入不平等的影响 --- data: cfps.dta --- discipline: economics
└──────── 研究方向 ────────┘    └── data ──┘    └──── discipline ────┘
```

- **研究方向** = 第一个 `---` 之前的全部内容
- **data** = 数据文件路径，或现成数据包 `pack:<名>`（`oss data list` 看有哪些）。**没给就停下来问用户**，别猜
- **discipline** = 学科，缺省 `economics`
- **style** = 可选，风格包名（`styles/<名>/` 要存在），有就按该刊的规矩和范文写
- **lang** = 可选，**`zh`（缺省）**或 `en`。缺省产出**中文论文 + 中文期刊体例的图**；
  **用户明说要英文论文才传 `en`**。`zh` 的连带影响：环节 5 的稳健性 `label` 用中文、
  环节 7 调 `/social-paper` 带 `--- lang: zh`、图一律 `--lang zh`。**只影响产出语言**——
  文献检索照旧中英都查（英文走接口、中文走 `oss lit import` 导入），分析、诊断、审稿全都不变
- **idea** = 可选，用户已经有的想法原文，自由文本，多长都行。**给了就走自带想法模式**（下文）
- **design** = 可选，逗号分隔的键值，锁死设计里最不该由模型改的五样（下文）
- **type** = 可选，研究类型：`因果` / `描述` / `测量` / `仿真`（也认 `causal` / `descriptive` / `measurement` / `simulation`）。**按「想下什么结论」定，不按用什么方法定**——想说「X 影响 Y」就是因果，哪怕只打算用普通回归（那样也要过识别审计）。给了就照抄进 `plan.json` 的 `research_type`（中文写法换成英文值；**不进 `design_locked`**——那里只认五个设计键，多一个键计划就读不进）；没给由环节 3 出题时按研究问题定
- **checkpoint** = 可选，逗号分隔：`idea`（**单数**——整理稿回给用户确认，带 `idea:` 时**缺省就停这一次**）、`ideas`（**复数**——陪审团砍完题后停下来让用户选）、`design`（因果审计判 FAIL 要换设计前停）、`none`（一次都不停）

  **缺省：`ideas`。**没带 `idea:` = 题目是模型出的，**那就是最该让用户过目的一步**。
  「这个题值不值得做」是整条链上唯一没有机械办法验的判断，也是选错之后后面全白做的
  那一步（WorkBuddy 那次跑了两小时、被自己的陪审团毙掉）。技术上站不站得住由陪审团判，
  **值不值得做由用户判**——分工不同，不能两样都替他做了。
  带 `idea:` 时缺省停 `idea` 那一次（题本来就是他的，停在整理稿更有用）。
  验收跑那种「一句话跑到底测流程」的场合写 `checkpoint: none`。

## 访谈：问的时候顺便教

缺 `data` 就停下来问——**但别问「data 是什么」**，那是在问他答不上来的问题。
问这个：

> 你想问的是**关于国家的事**（比如「哪些国家生育率降得快」），
> 还是**关于人的事**（比如「什么样的人生得少」）？
>
> - 关于国家 → 我这儿有现成的（`oss data list` 里 `本地已有` 的那几套），直接用
> - 关于人 → 得要个体调查数据。GSS（美国）现成可用；
>   CGSS、CFPS 要申请，我可以告诉你怎么申请
> - 你自己有数据 → 把路径给我（CSV / Excel / `.dta` / `.sav` 都行）

**这一问是有内容的**：它顺手把「你这个问题需要什么层次的数据」教给了用户，
而层次不匹配正是最贵的一种错——拿国家数据回答关于人的问题，一路不会报错，
只会产出识别分很低的设计，跑到陪审团那儿才被毙掉（WorkBuddy 那次两小时就这么没的）。

**用户自己带数据时再问一句**，因为有些事只有他知道、数据里看不出来：

> 关于这份数据，有什么我该知道的吗？如果是抽样调查：该用哪个权重（横截面还是面板）？
> 有没有分层或初级抽样单位变量？（另外比如：99 是拒答；某年之后换了口径；
> 这几道题只有 A 卷问了）

他说了就 `oss trace save --step data_notes --note "<他的原话>"` 记下来，
环节 1 画像时对照着看，写论文时进数据那一节。**没说就不追问**，一句带过。

**data 可以给多份，用逗号隔开；自己的文件和数据包可以混用：**

```
--- data: qog.csv, internet.csv
--- data: my_survey.dta, pack:qog
--- data: pack:cgss
```

`pack:<名>` 先 `oss data get <名> --run <运行目录>` 拿到本地（见环节 1）；
**要申请的数据集拿不到就停下来把申请办法转告用户**，不要拿别的数据顶替。

`--- data: sim:<货箱目录>` 表示这份数据来自仿真货箱，不是普通数据文件——箱子
要么是 `/social-sim` 一段话跑出来的，要么照 `docs/user/sim-box.md` 手工装的；
环节 1 认出这个前缀会走专门的 sim 分支（先验货、再入库、再取数据），细则见
环节 1 的 sim 分支一节。

多份数据意味着**第一件事是把它们拼起来**，用 `oss merge`（见环节 1）。
**不要自己写拼接脚本**——拼数据是这条链上最危险的一步，因为它错了不报错。

给了 `crosswalk.csv` 之类的对照表就用 `--map` 传给 `oss merge`。

## 自带想法：`idea:` 与 `design:`

```
<研究方向> --- data: ... --- discipline: ... --- idea: <想法原文> [--- design: <五个键>] [--- checkpoint: ...]
```

**`idea:` 非空 = 用户已经有题了，你不出题。**这一段自由文本，至少要能看出 X、Y 与预期方向；
机制、理论对话、识别思路有就写。例：

```
--- idea: 资本市场对企业的错误定价越严重，企业的供应链风险越高；机制是管理层短视与过度自信；
        预期为正向；A 股制造业 2012–2024 企业—年份面板
```

拿到它之后**整段原文一个字不改地传给环节 3**，由 `/social-idea` 的整理模式办：
整理 → 陪审 → 确认 → 冻结（细则在 `.claude/skills/social-idea/reference/tidy-mode.md`）。
`ideas.json` 的顶层 `direction` **就写这段原文**——锚点门比对的是这个字段，
**原文不动，锚点就是用户的话**。

**`design:` 锁死五个键**，都可缺省，缺省的由你定：

```
--- design: outcome=Risk, treatment=Misprice, fe=firm+year, cluster=firm, estimator=ols_fe
```

用户那边的写法与 `plan.json` 里的字段名**不是一一同名**，环节 5 照这张表抄：

| `design:` 里的写法 | 进 `plan.json` 的哪个字段 | 值怎么变 |
|---|---|---|
| `outcome=Risk` | `outcome` | 原样 |
| `treatment=Misprice` | `treatment` | 原样 |
| `fe=firm+year` | `fixed_effects` | 按 `+` 拆成列表 `["firm", "year"]`，顺序不算数 |
| `cluster=firm` | `cluster_level` | 原样 |
| `estimator=ols_fe` | `estimator` | 原样 |

`estimator` **只认工具箱清单**（`ols_fe` / `did` / `did_cs` / `event_study` / `iv` / `iptw` / `rdd` / `describe` / `logit` / `ologit` / `mixed`）。
用户写了清单外的值，**停下来告诉用户**，不替换、不猜一个近似的。

**这五个键要抄两份**：一份填进 `plan.json` 的对应字段，一份原样进
`plan.json` 顶层的 `design_locked`。`design_locked` 的**键名用右边那一列**
（`fixed_effects` / `cluster_level`），**不是** `fe` / `cluster`——写错会让
`oss run` 直接拒绝读这份计划（`plan.json` 的 schema 禁未知键）。
写完之后怎么自核，见环节 5。

**没有 `design:` 的输入，`design_locked` 这个字段压根不要写；给了 `design:` 就写，与有没有 `idea:` 无关。**

拆完先复述一遍给用户确认，一行就够：

> 方向「XXX」｜数据 `xxx.csv` + `yyy.csv`｜学科 economics

**每个 `oss` 命令都要带同一个 `--run`。**

注意两条 shell 的脾气，**它们方向相反**：

- **变量存不住**：`RUN=...` 这种赋值到下一条命令就没了。路径写死成字面量
- **工作目录却存得住**：上一条命令里 `cd` 过的目录会带进下一条命令。
  **所以永远不要 `cd`**——两次真跑各出过一次事故：`cd runs/xxx` 之后
  再用相对路径，产出落进了 `runs/xxx/runs/xxx/` 嵌套目录，
  或者报「文件不存在」。所有命令都从项目根、用相对路径跑：

```bash
mkdir -p runs/r20260823_1530        # 名字你定，之后不再改
oss profile data.csv --run runs/r20260823_1530
oss lit search "..."  --run runs/r20260823_1530
```

## 仿真来源：`/social-sim` 的参数拆法

`/social-sim` 是另一条独立命令，不是 `/social-research` 认的参数——用来从一段
设计描述跑出仿真货箱，跑完再用 `--- data: sim:<箱>` 接回这条主链（见上文
`sim:` 一段）。它自己的拆法：

```
<方向> --- simulator: oasis --- design: <一段话> [--- budget: <元>] [--- checkpoint: design|none]
```

- **simulator** 必给，模拟器插头名（`oasis` 或 `agentsociety`，名单以 `oss/sims/__init__.py` 的 `KNOWN` 为准）
- **design** 必给，自由文本，至少要能读出条件、人数、每组重复次数、轮数、
  访谈波次与问题；读不出就停下来问用户，不替用户猜
- **budget** 可选，单位元，给了就跟预计费用比对
- **checkpoint** 可选，`design`（缺省，整理稿写完停一次等用户点头）或
  `none`（一次都不停）

完整规矩（拆参数细节、七步操作手册、五条铁律）**不在这里重复**——见
`.claude/skills/social-sim/SKILL.md` 与 `.claude/skills/social-sim/reference/run-order.md`，
那份技能是这套参数拆法的唯一权威出处，这里只负责指路。
