# 写之前先读三样东西

**① `results.json` 的 `diagnostics`**

它写清了标准误是怎么算的、吸收了多少自由度、丢了多少缺失。
**这些必须写进「数据与方法」**——审稿人第一个问的就是这些。

**② `power.json` 的判词**

`fail` → **不许写。**功效 FAIL 是设计失败，不是可报告的结果——`oss paper check` 会拒绝。
回主链换结局 / 换样本 / 换题目（`oss route` 的 `power_fail` 处方；**换题目要用户点头**），拿到 pass 或 gray 再来。
描述类（`power.json` 的 `mode` 是 `precision`）不在此列：精度判 `fail` 不停，`precision_low` 处置了照样写，局限写明这份数据分不出小于多少的差别（主链环节 4「描述类题目按精度判」）。

**②′ `route.json` 的处方**：先跑 `oss route --run <运行目录>`。`must` 级没处置，校验拒绝；
标了 `disclosed` 的每一条，局限里要有对应的那一句——写那个局限本身，不写「处方 / 审计说」。

先看 `treatment_icc_source`：写着「假定」说明 ρx 是猜的（默认按 1 算，
相当于假定处理变量在簇内完全不变）。**个体层面的自变量不是这样，
这会让功效被系统性低估**——这一点要在局限里如实写，两个方向都写。

再看 `verdict_fragile`。为真时说明**换个假定参数判词就翻**，
`{{power:sensitivity}}` 里写明了在哪里翻。**这一段必须引进局限**：

> 「改这个参数就能改判词」是审稿人一定会问的，
> 而它只能用一张可核对的表回应，辩解没有用。

不敏感时也要写一句「判词对折价系数与灰区上下界均不敏感」——那是正面证据。

- `fail` → **样本量撑不起这个设计。**这不能瞒着，要写进讨论的局限
- `gray` → 落在灰区，看有没有跨模型的裁决意见，有就照实引述

**③ `literature.json` 的 `notes`**

如果里面写着「只有 28% 的文献带摘要，方法缺陷类空白因此检测不到」，
那意味着**这次的文献覆盖是残缺的**——写进局限，别当成完整综述。

**中文文献的新颖性主张有单独一条闸**：语料里没有 `language` 为 `zh` 的记录（历史层 `oss lit search --zh` 命中，或 `oss lit import` 导入进来的）时，「首次」「尚无研究」这类说法**不能用**——中文那半是盲的，你没有能力知道有没有人做过。（看 `literature.json`：`hits_by_source.openalex_zh` 是历史层命中数，`notes` 里「导入 …：N 条进语料（中文 M 条）」是导入数；两个都是 0 就没有中文记录。）
有了也**只对历史层（OpenAlex 里 20 本中文核心刊，收录基本止于 2018 年）和导入的那一批覆盖到的范围有效**，**要把范围写明**（例：「在我们检索到的 2018 年前中文核心期刊与导入的 N 篇题录中，未见……」）。

**新颖性主张有门**：`reading/index.json` 里读到全文的篇数不到 3 篇、或不到精读集的一半，
「first study」「no prior work」「nobody has」「首次」「尚无研究」一律被 `paper check` 拒绝。
够了也只能写有范围的说法："among the N studies we reviewed in full, none …"。
最接近的先例（`reading_cards.json` 里 `relevance` 为「直接」的）必须读到全文，读不到就不能声称比它新。
