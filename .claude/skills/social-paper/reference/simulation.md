# 仿真论文的说话规矩（`sim:` 来路）

运行目录带 `sim_state.json`（`oss sim import` 写的入库档案），**或者**计划里
`research_type` 写 `simulation`、`also` 里有 `simulation`，就是仿真论文——数据来自
LLM 智能体模拟，不是对真实世界的观测。下面五条是这份体裁专属的措辞与结构规矩，
跟五节各写什么（`sections.md`）配合读，不是替代它。

**声明为仿真却没入库货箱的，`oss run` 会拒**（`plan.simulation.box_missing`）：
没有那份档案，配料单那几道检查一条都跑不了，验货（波次全不全、小人覆盖全不全、
重复够不够）也整条绕过去了。先 `oss sim check` 验货、`oss sim import` 入库。

## 一、结论句限定在本模型内

仿真跑出来的效应，是**这个模型、这套提示词、这批小人**在这套条件下的行为
反应，不是对现实世界的断言。结论句一律限定在**「在本模型内」**（英文对应
`within this model` / `within this model's dynamics`）的范围内——
不写"在现实中会""这意味着人们会"这类跨出模型边界的句式。

**两道检查，方向相反，要分清楚**：

- **全文一次都没限定就拒**（`sim.no_scope_limit`）。认这几种写法：在本模型内 /
  在模型内 / 在本模型的设定下 / 在本模型框架内 / 在本模型的边界内 /
  within this (the) model / within the simulated model / within the model's dynamics。
  **这张清单是「必须出现」型的**——你写了个清单上没有的等价写法，结果是被误报，
  不是被放过；觉得被误拦了就来提，清单会加。引号里的不算（受访者原话不是你的限定）
- **跨出边界的句子逐句警告**（`sim.reality`，不拦路）。这张是**违规清单**，只有五个词
  （现实中将 / 现实世界会 / 政策应当立即 / 现实中会 / 这意味着人们会），
  **换个说法就漏放**——所以别把「没被警告」当成「写得没问题」，那一层靠审稿人

## 二、方法节：配料单逐项报，哪几项有检查、哪几项没有

方法节不是选择性摘录配料单，是**逐项报**——`sim_state.json` 的 `meta` 字段
就是数据源（跑前人填的 12 项，见 `docs/user/sim-box.md` 第二节）。

**七项有代码牙齿**（`paper check` 会去正文里找它的值，找不到就拒）：

| 配料单项 | 论文里要出现什么 |
|---|---|
| `simulator` | 模拟器名，不区分大小写 |
| `simulator_version` | 版本串（`0.3.1`） |
| `model` | 模型名，**写带日期的完整版本号**（`gpt-4o-2024-08-06`），不写「最新版」 |
| `model_provider` | 走哪个网关（同名模型走不同网关，路由与量化可能不同） |
| `temperature` | 温度这个数（`0` 也查得动） |
| `rounds` | 轮数这个数 |
| `n_reps` | 重复次数这个数，**且要跟「重复 / rep」写在同一段** |

数字查的是**独立成数**：轮数 5 不会被正文里的 `25` 顶掉，温度 `0.7` 不会被 `10.7` 顶掉。
配料单里名字短于三个字符的（`model: "m"`），检查会说「核不动」并要求写全——
一个字母在任何一篇论文里都找得到，那种检查是空问。

**这七项的正文里可以直接写小数**：配料单里的值是本次运行自己的产出，
不受「正文不许有裸小数」那条铁律管（`0.7`、`0.3.1` 照写不误）。

**五项没有任何机器兜底**，报不出就是不诚实：

| 配料单项 | 为什么没牙齿 |
|---|---|
| `prompts` | 提示词原文，不是转述——自由散文，查它就得读懂意思 |
| `population` | 同上 |
| `interview_plan` | 同上 |
| `contamination_note` | 同上 |
| `conditions` | 键是机器标识（`threshold_low`），论文里本来就该用人话描述条件，硬查字面会误拦正当写法 |

这五项由**审稿人**看（`social-review/reference/simulation.md` 第一条）。

## 二之二、ODD 七节靠什么交代

Grimm 等（2020）的 ODD 协议是仿真论文的写作标准。「这段话有没有把第四节交代清楚」
是纯语义判断，做成检查就是一道换个说法就失灵的门，所以**不做语义核查**——
七节映射到盘上已有的事实，报齐这些事实就等于交代了大部分：

| ODD 七节 | 靠什么交代 | 有牙齿吗 |
|---|---|---|
| ① 目的与模式 | `plan.simulation` 的 `mechanism`（模型里什么导致什么）+ `pattern`（该重现哪个已知模式） | ✅ 契约必填 |
| ② 实体、状态变量、尺度 | 配料单 `population` + `states.csv` 的列 | ⚠️ 列有（验货查），`population` 没有 |
| ③ 过程概览与调度 | 配料单 `rounds` + `interview_plan` | ⚠️ `rounds` 有，`interview_plan` 没有 |
| ④ 设计概念 | —— | ❌ **全靠你写，审稿人来看** |
| ⑤ 初始化 | 配料单 `population` + `conditions` | ⚠️ `conditions` 有（但只核在不在货箱里），`population` 没有 |
| ⑥ 输入数据 | 配料单 `prompts` + `simulation.real_benchmark`（若有） | ⚠️ 对照数据有，`prompts` 没有 |
| ⑦ 子模型 | 配料单 `model` / `model_provider` / `temperature` / `prompts` | ✅ 前三项有 |

**第四节「设计概念」一点机器兜底都没有**，而它恰恰是 ODD 里最容易含糊过去的一节
（涌现、适应、交互、随机性、观测）。这一节写不写得清楚，只有审稿人看得出来。

## 三、`downgrade=true`：通篇初步/探索性措辞

`sim_state.json` 的 `downgrade` 为 `true`（某条件 rep < 3）时，**全文**（不
只是局限那一节）改用「初步/探索性」一类留有余地的措辞——摘要、结果、讨论
一致收紧。局限节必须含降级句**原文**（`oss/core/simbox.py` 验货打出来的
那句，逐字抄，不转述）：

> 「单次模拟无法区分随机波动与真实规律」

## 四、局限五件套，一条不能少

除了 `sections.md` 原有的局限清单，仿真论文另加五条，逐条对应：

| 件 | 写什么 |
|---|---|
| 小人效度 | 模拟出来的智能体行为在多大程度上映射真实人类行为——这是假设，不是已证实的事 |
| 版本漂移 | 模拟器/模型换个版本，结果不保证可复现——`simulator_version`、模型版本与所走网关（`model_provider`）都要写实，同名模型走不同网关，路由与量化可能不同，不写"最新版" |
| 提示词敏感 | 访谈问题、角色设定换一种措辞，结论可能不同；没跑过提示词变体的，如实说没跑过 |
| 污染声明 | `meta.contamination_note` 原样写进来——模型训练语料是否可能见过这个议题，"不确定"也要写 |
| 单一模型 | 结果反映的是这一个 LLM 的行为，不能推广到"大模型普遍""AI 普遍" |

## 五、wave 和真实轮次的对应

`states.csv` 的 `wave` 是访谈发生的顺序号（0,1,2…），**不是**模拟内部的
轮次号——真实对应第几轮，权威出处是配料单 `interview_plan`。正文提到某一波
访谈时，按 `interview_plan` 把 wave 翻译成"第几轮之后的访谈"讲清楚，不要
让读者以为 `wave 3` 就是模拟跑到了第 3 轮。
