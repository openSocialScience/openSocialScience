# 五节各写什么

## 摘要

一段，**300 字以内**。四句：问题 → 用了什么数据 → 主要发现 → 这意味着什么。

**要有具体的量，而且是读者不看模型就懂的量。**「管理与专业阶级的过劳概率低
{{result:main.coef}} 个百分点」——不是「系数为 {{result:main.coef}}」。
数字一律从占位符引，不手打。评审：「摘要没有任何具体数字」——没有数字校验会警告。

**不要写这四样：标准误、p 值、最小可探测效应、样本量。**
2026-09-23 实测 59 篇已发表的中文摘要（人口研究、中国人口科学、管理世界等），
**这四样一篇都没有**；而我们生成的 8 篇 100% 都有。它们在正文和表里照旧完整报，
只是不进摘要。写了校验会警告。

**不要写稳健性检验**，那是正文的事。实测我们的摘要把三到四成的句子花在稳健性和局限上
（一篇 16 句里 7 句），已发表的基本不写。最多留一句限定适用范围的话。

**不要写「本文发现了显著的影响」**——显著不等于重要，写效应的实质含义。
「本文」在开头出现一次就够（已发表的摘要「本文 / 我们」中位数是 0 次）。

**末句给含义**，别停在数字上：已发表的 47% 会说这个发现意味着什么，我们只有 25%。

长度实测：我们生成的 8 篇中位 480 字、全部超 300 字；已发表的中位 230 字。
上限依据《中国社会科学》发文格式（300 字以内）；GB/T 7713.2—2022 说报道性摘要 400 字左右。

## 引言

进入哪个理论对话（`ideas.json` 的 `theory_hook`），
现有文献缺什么，本文补什么。

**不要罗列文献**。写「谁说了什么、彼此怎么分歧、你站在哪」。

## 数据与方法

**加没加抽样权重要写一句**，两种情况都写——读 `results.json` 的 `diagnostics.抽样权重`：
加了就写按哪一列加权、有效样本量多少（**置信区间该按有效样本量读，不是按行数**）；
没加就写「本文报告未加权估计」并说明含义。**沉默是不行的**：读者分不出
「这份数据没有权重」和「有权重但没用」，而这两件事对结论的意思完全不同。

数据来源与结构（看 `profile.json` 的 `structure`）、
关键变量怎么测的（看 `binding.json`——**代理变量要说是代理**，按 `construct_def` / `measures` / `gap`
三栏写成一句：「理论要的是 X；我们用 Y 测它；两者的差距是 Z，会让估计偏向 W」）、
样本怎么来的（`diagnostics.样本构建` 或 `{{table:sample}}`：原始多少、筛掉多少、去缺失掉了谁）、
识别策略、`diagnostics` 里的技术细节。

**用了数据包的（QoG、V-Dem、GSS……）要写明数据集名、版本，并引用它**——
引用格式在 `data/<名>/<名>.meta.json` 的 `citation` 里（以码本首页为准），
先 `oss lit add <DOI或标题>` 把它抓进语料再用 `{{citep:...}}` 引；`paper check` 查论文里有没有出现数据集的名字。

**派生变量必须交代构造式**。`binding.json` 里 `status` 为 `derived` 的都要写。

## 结果

主效应用占位符。控制变量的系数如果反直觉，说一句。

**不要把统计显著说成「证明」。**

**对比两个规格的主效应时，两个数必须是同一个量。**含交互项的模型里，
处理变量的系数是**参照组的条件效应**；去掉交互项才是平均效应。
「限制样本后效应从 {{robust:R0/main.coef}} 掉到 {{robust:R11/main.coef}}」——
一个含交互项一个不含，比的是两种量，`oss paper check` 会警告。
要比就比同一设定下的两个样本。

**不显著的系数要配最小可探测效应。**`{{result:main.mde}}`（80% 功效、5% 双侧）
说明这个样本能测出多大的效应；比它小的效应本来就测不出来——
「没有效应」和「测不出来」是两句话，读者要知道你说的是哪句。

> ⚠ **但不许反过来用它下排除的结论。**
>
> ```
> 错：最小可探测效应是 0.008，本文没测出来，所以能排除快于 0.008 的收敛
> 对：最小可探测效应是 0.008，本文没测出来，所以不能排除一个更慢的移动
> ```
>
> MDE 的意思是「**若**真值有这么大，本样本有八成把握测出来」。没测出来只说明
> 「要么没有，要么这次运气不好」——**那个值本身还在置信区间里，排除不掉**。
>
> 真要主张「排除」，得报**置信区间上界**，或者做等效性检验（TOST）。
> 十一轮 CGSS 那次真跑，这句话在中英摘要与结论里各出现一次，
> 三道机械的门全部放行，是跨模型审稿抓出来的（`oss paper check` 现在会警告）。

## 讨论

发现意味着什么、**局限**、下一步。

局限这一节必须包含：

- `power.json` 判 `gray` 的话，功效多少、对多大的效应才够（`fail` 根本到不了这一步）。描述类按精度判：`gray` 或 `fail` 都写，写这份数据分不出小于多少的差别
- `route.json` 里标 `disclosed` 的每一条处方
- `literature.json` 的 `notes` 里的覆盖缺口
- 识别策略本身的边界（固定效应排除不了随时间变化的遗漏变量）
- `binding.json` 里的代理变量
- **`review_plan.json`（因果审计）的每一条意见**，一条一句交代：承认、后果、为什么没法解决。
  审计判 FAIL 不要求换设计，**要求如实写出来**——审稿人会拿着审计报告逐条核。
  **但不许提「审计」**：写「处理时点可能内生，因为……」，不写「审计指出处理时点内生」。
  你不同意审计的地方，写进收尾说明和 `oss trace save`，**不进论文**
- `prep.py` 里构造、分析用到的每个派生列的构造式（`oss paper check` 会查有没有提到）
- **判词里 `cross_family` 是 `false` 时**：一句话写明本文的审稿由同一模型完成、
  不构成独立验证（`oss eval` 的 `self-review-disclosed` 会查）。
  **只写这个事实，不写「审稿」两个字之外的过程**——照上面那条铁律，
  写「本文的审稿由同一模型完成，不构成独立验证」即可，不写谁审的、审了几轮

复审之后还有没处理的审稿意见，另起一小节 **Open questions / 尚未解决的问题**。

**必须逐条写，一条一段**（`第一，…` `第二，…` 或 `- `）：这一条**是什么**、
**为什么现有数据解决不了**、**要解决它需要什么**。

**这不是「未来研究方向」。**六次跑的实测：五次里四次，5 到 16 条未决意见等于没交代——
两次根本没写这一节，两次写了但通篇是泛泛的展望，**一条具体的都没点**。
`oss eval` 的 `open-items-accounted` 现在专门查这个：**有节没逐条，照样判不过。**

**照旧不许提「审稿」两个字**（铁律二）：写「共期的宏观冲击无法与政策时点分开」，
不写「审稿人指出共期冲击问题」。**写的是问题本身，不是谁提的。**

**局限写得诚实，比结论写得漂亮重要。**
