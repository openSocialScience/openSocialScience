# ⑤ 经验预检与重排

**这一段是这次重构取回来的东西**：便宜的经验信号，在**选题之前**参与排序。
以前是先选定一个题、再去验证它——验证结果改变不了选择，等于没参与。

## 权限：只许重排，不许生成

这一段第一次看见**真数据**，也是权限最窄的一段：

> **只许重排，不许生成。**

看见真数据就想改题是本能——「这一列的分布不错，不如改成问它」——那是数据在出题。
排序可以整个翻过来，题目一个字不能新加。候选数在这一段前后必须不变（`generated_n` 认的就是它）。

## 对谁跑：最多前 8 个

④ 存活下来的候选，按 ④ 的顺序取**最多前 8 个**。这是成本上限，不是质量判断——
8 个之后的不是「不够好」，是「这一轮没排上」，它们照旧留在文件里。

真跑下来贵了就下调，别往上加。

## 三级信号，从便宜到贵

### 一 · 构念能不能落到真变量上

```bash
oss bind --run <运行目录> --idea <idea_id>
```

`core_ok` 为 false 就是 treatment 或 outcome 绑不上——**这题这份数据做不了**，
按下面「做不了不扣分」分流，不是淘汰。

> ⚠ **绑不上不等于不存在。**社科的变量名天生简陋（一份名叫「政府信任」的文件里，
> 列名可能是 `a35`、`b12`）。先用完整变量清单按**标签和题干**找，找不到再说绑不上；
> 绝不能因为按列名搜不到就判「这份数据没有这个构念」。

### 二 · 这题在这份数据上测不测得出来

```bash
oss power --run <运行目录> --idea <idea_id> \
          --effect-source "⑤ 经验预检：只读 mde，不用文献效应量" \
          --out prescreen_<idea_id>.json
```

**读 `mde`，不看 `verdict`。**

- `mde` 是**最小可测效应**（Cohen's d，目标功效 0.8）：这份数据最小能测出多大的效应。
  它**只取决于有效样本量**，不随 `--effect` 变——所以预检不必先有一个效应量估计。
- `verdict` 在这一步**没有意义**：它是拿 `--effect` 算出来的，而预检阶段那个数还不知道。
  盯着判词看，就会退回「拿命令行缺省的 0.2 算出 pass」那条老路——`effect_size_source`
  那一栏一直在拦的正是这件事。

**描述类的候选读 `precision_halfwidth`**（95% 区间半宽，标准差为单位），不读 `mde`：
描述研究回答「是什么」，不测一个效应，按功效判会把它误停。判据是半宽跟**有意义的最小差别**比。

> `oss power` 会写一份 `power.json`（`--out` 是在它之外另存一份）。预检轮着跑完，
> 盘上那份是**最后一个候选**的——这没关系，选定题目之后环节 4 会按选中的那道题重算。
> 中间没有任何一步读 `power.json`。

### 三 · 焦点变量本身像不像样

缺失率、组内变异、取值分布。绑上了但九成是缺失、或者根本不随时间变的，
在 `prescreen.note` 里写明——这不是淘汰理由，是排序依据，也是论文局限的素材。

## 重排

三级信号跑完，把候选**重新排序**，并把证据挂到每条的 `prescreen` 栏：

```json
{"bound": true, "mde": 0.031, "coverage": 0.92, "note": "结局缺失 8%，组内变异充足"}
```

排序不是算分。把证据摆出来，顺序由你按「哪个题这份数据真答得动」定，
理由写进收尾说明。原来排第一的一跑发现构念绑不上、掉到底，是这一段该有的样子。

## 做不了不扣分

> **做不了不扣分。**

重排有个自带的危险：能跑的题会自动浮到前排，**更值得做但这份数据做不了的题会沉底**——
而这个降级过程看起来非常客观。防线是把它们**分流**，不是扣分：

- 留在 `ideas` 里，一条都不删
- 编号写进 `ideas.json` 顶层的 `unreachable`（清单乙）
- 每条在 `needs_extra_data` 写清**缺什么、去哪拿**——只标「做不了」不说缺什么，
  用户就没有去拿数据的路

**两份清单都要交付**：甲是这份数据能做的（排过序、带证据），乙是更值得做但做不了的。
乙栏不是废纸篓，是给用户决定要不要去申请数据的依据。

## 全灭时回退，至多一次

前 8 个**全部**在这一段死亡（比如焦点构念一个都绑不上），说明发散段那一轮是对着
错误的数据想象做的。回 ③ 重跑一轮，这次带上「这份数据实际能测什么」。

**至多一次。**这是全流程唯一的回路，没有这条上限它就是死循环。
回退一次之后仍然全灭，就如实告诉用户：这份数据撑不起这个方向，
把清单乙和缺什么一起摆给他。

回退产生的新候选**重新计一次 `generated_n`**（等于两轮之和），旧的一轮照旧留在文件里。

## 完成条件

- 跑过预检的候选都有 `prescreen` 证据
- 候选数没变（`generated_n` 不变，一条没删没加）
- 做不了的都进了 `unreachable` 且写清了缺什么
- 收尾说明里报三件事：各候选的 `mde`（或半宽）、重排前后的顺序变化、清单乙有几条各缺什么
