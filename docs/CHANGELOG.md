# 更新日志

本文件参照 [Keep a Changelog](https://keepachangelog.com/zh-CN/1.1.0/)（保持更新日志）的写法：
新版本在上、旧版本在下，每个版本按改动类别分节——本文件用「新增 / 修复 / 文档」三类。
版本号按 [语义化版本](https://semver.org/lang/zh-CN/)。

## [0.5.0] - 2026-10-07

0.4.0 之后的 311 次提交。下面按能力归类，不逐条列提交。

### 重要变化

- **许可证从 MIT 改为 Apache License 2.0**。0.5.0 起按 Apache 2.0 发布；0.4.0 及更早的版本仍是 MIT。
  可选依赖里那个 AGPL 组件的说明见 `NOTICE`
- **程序输出里的「门」统一改叫「检测」**：报错、提示、`oss schema` 字段说明、MCP 说明都跟着改了。
  例如 `探索门拒绝：` 现在是 `探索检测未通过：`，`锚点门：` 现在是 `锚点检测：`。
  依赖这些文字做匹配的脚本要跟着改；JSON 的键名与退出码不变

### 新增

- **描述类研究**：新估计量 `describe`，给各组均值与比例、对参照组的差、趋势斜率、分布分位数，
  区间按抽样设计算；描述类题目按精度判（区间半宽比有意义差别），不按功效判；配套分组描述表、
  处方和合规规则
- **调查数据**：画像能认出权重、分层、初级抽样单位、插补标记；按抽样设计算标准误
  （分层 + 整群，泰勒线性化，用 t 分布）；所有估计量都真加权，不再有拒跑权重的估计量；
  有效样本量按整群与权重的设计效应折算；GSS、CGSS、CFPS 补登记抽样设计
- **测量类研究**：计划要写构念、指标和效度证据；分「造尺子」和「用尺子」两路检查，
  只报信度不算给了效度证据，跨组比较要先做测量等价检验
- **仿真类研究**：计划要写机制与模式；仿真输出要先入库验货；结论必须限定在模型内；
  主张代表真人就要跟真实调查对账（方差比、关系方向）
- **因果研究加强**：计划要写估计量三步，控制了中介或碰撞变量、用结果变量筛样本都会被拦；
  工具变量报有效 F、AR 区间，弱工具时正文必须引 AR 区间；事件研究与分批 DiD 报预检功效与
  breakdown 值；`ols_fe` 的因果结论报 Oster δ 和 E 值；七条因果处方
- **新估计量**：二元与有序 logit、多层模型（随机截距、ICC）、逆概率加权与双稳健估计
- **计划体检**：正式跑之前先体检计划，配对列、嵌套分组这类问题会开处方，没处理就不跑（退出码 6）
- **中文文献**：网页全文导入，并判断「这是不是一篇研究论文」；中文期刊 PDF 的篇名抽取从 44% 提到 94%；
  作者抽取；英文稿引中文文献会罗马化并附英译
- **风格包**：管到页面版式（纸张、字体字号、注文），字数支持区间；新建三个中文期刊的风格包
- **论文体例**：中文论文按三线表、夹注排版，中文摘要有写作规范；英文稿按社会学通例
  （星号档位、标准误进括号）；表和图里印变量的中文名，不印列名
- **图**：默认中文，两套按真实期刊量出来的样式，黑白打印也看得清
- **交付前核对**：导出前核对审稿人看的稿子和交出去的是同一份
- **找题目**：起点改为四个来源，经验预检参与排序，文献走双通道，用户自带 PDF 也能用
- **一句话安装**：新增 `INSTALL.md`，用户对 Agent 说一句话就能自动安装
- **`CITATION.cff`**：GitHub 仓库页可以一键复制引用格式

### 修复

- **平行趋势联合检验的检验尺寸不对**：长窗口时会误拒约三成，已修正
- **Oster 偏误调整式写反了**：沿用 StatsPAI 时比值写倒，改回原文公式；
  主回归与辅助回归现在用同一批样本
- **HC1 标准误会爆内存**：原来建 n×n 矩阵，大样本会撑爆；改写后结果逐位不变
- **测量类研究的九个绕行漏洞**：例如 `kind` 留空、把测量放进 `also`，原来能整套绕过检查，现在都堵上了
- **论文检查漏查的写法**：手打小数（省略 0、紧挨汉字）、显著性说反、裸引作者姓、因果措辞的八种写法
- **读 GBK 编码的 .dta 不报错但标签全是乱码**；双栏 PDF 逐行交错读；`lit fetch` 冲掉 `lit import` 导入的索引
- **图的排版问题**：森林图被注释撑扁、缺失值图过高、簇结构图标题重叠
- **中文稿用了直角引号「」**：横排简体改用“”
- **缺失值编码**：连号哨兵值整体识别，标签按子串识别，进回归的列在 `oss run` 时再查一遍
- **CI**：干净检出后全部测试通过

### 文档

- README 重写：描述改成更直白的说法，加三个完整实例、工作流海报和新的首屏图，补引用格式
- 架构文档（ARCHITECTURE.md）重写，从 288 行压到 233 行
- 新增 `NOTICE`，集中列出第三方组件的来源和许可
- 补上仿真怎么用

## [0.4.0] - 2026-09-14

**这是第一份有更新日志的版本。** `0.3.0` 是 2026-08-23 那次骨架提交（阶段 0：跑通链路、
产出全假），此后从没升过版本号——中间几百次提交事实上都在这一版里。下面按能力归类，
不逐条列提交。

### 新增

- **九阶段研究链**（`.claude/skills/social-research`）：数据画像 → 文献检索 → 找空白/想
  题目 → 可行性（绑定构念、算功效） → 写计划 → 跑分析 → 写稿 → 识别审计（7.5，因果研究
  插入） → 桌审/三位审稿人/编辑综合 → 收尾，全程留痕（`trace.jsonl`）
- **程序检测与 `oss eval`**：分析计划校验、探索检测、锚点检测、研究类型检测（见下）等程序检测，不通过就不能继续；
  `oss eval` 对着运行目录核执行者有没有照说明书做，`oss eval --behavior` 从留痕看这次
  是怎么跑的（换了几次题、审了几轮、被拒几次）
- **跨模型审稿**（`oss/host/reviewer.py`）：审稿人与执行者的模型家族检查，流式调用，
  轮次检测（默认最多两轮，第三轮起要 `extra_round` 加审并配 `why`）
- **文献流水线**（`oss/api/lit.py`）：检索（`search`，含中文白名单 `--zh`）、手动加一条
  （`add`）、题录导入（`import_file`）、滚雪球扩语料（`snowball`）、拿全文
  （`fetch`，按 OpenAlex / 落地页 / Unpaywall / CORE 顺序试）、筛选（`screen`）、读书卡
  （`cards`，局限引文逐字核对原文）、引文转述核对（`verify`，叙述式 `{{cite:...}}` 与
  括注式 `{{citep:...}}` 都查）
- **六种估计量**（`oss/core/analysis.py` 的 `SUPPORTED_ESTIMATORS`）：`ols_fe` / `did` /
  `did_cs`（Callaway–Sant'Anna，分批处理） / `event_study` / `iv` / `rdd`，带诊断；分批
  实施的因果设计自动附带按批展开的事件研究
- **抽样权重堵漏**：`ols_fe` / `did` / `event_study` 真加权（`WEIGHTED_ESTIMATORS`）；
  `did_cs` / `iv` / `rdd` 拿到权重直接拒跑并说明怎么办，不再悄悄按不加权算
- **研究类型主轴**（`oss/gates/research_type.py`、`oss/core/causal_wording.py`）：因果 /
  描述 / 测量 / 仿真按想下的结论分（不按方法），随锚点首次声明即锁定、只许从因果降为
  描述；因果措辞两档检查（明确说法硬拦、模糊说法标出交识别审稿人判）；识别审计按
  `research_type == causal` 触发，`ols_fe` 下因果结论也要过审计
- **多宿主支持**（`oss install-skills`、`oss/hosts/`）：Claude Code、Codex、dsh、
  WorkBuddy、openclaw 五份宿主档案；`oss mcp serve`（stdio，零新依赖）把 `oss/api/` 的
  函数注册成 32 个 MCP 工具
- **CI**：新增 `.github/workflows/tests.yml`（见「文档」一节的说明）

### 修复

- **`.env` 查找规则统一**（`oss/core/envfile.py`）：原来三处各自抄一遍「cwd 向上找」，
  只在仓库目录里跑才找得到；新增用户级落点 `~/.config/oss/.env`，`oss doctor` 的
  「未配置」消息按人话说清找过哪些地方
- **`oss lit verify` 漏核括注式引用**：原来只查叙述式 `{{cite:...}}`，`{{citep:a;b}}`
  这类一次引几篇的括注式引用一条都没查过，现在两种都核
- **中文起稿模板自己的注释过不了自己的过程词检查**：模板里含「占位符」一词的两处 HTML
  注释撞进黑名单，改了措辞、不改检查
- **pypdf 没声明成依赖**：读 PDF 的兜底路径（没装 PyMuPDF、或 PyMuPDF 打不开坏 PDF 时）
  要用它，`pyproject.toml` 却哪儿都没写——照 README 装完一读 PDF 就报错；现在进了基础依赖
  （`pypdf>=3.0`）
- **逐字冻结的输出测试缺附加依赖时判红**：基线是装了 statspai / matplotlib 时录的，缺了
  它们，那 7 条命令本来就该说另一句话；现在按表自动跳过、不判红，依赖装齐时照样逐字比

### 文档
