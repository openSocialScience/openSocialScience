# 使用说明

安装 → 配置 → 用。三步，照抄即可。

---

## 一、安装

**先装好**：Python ≥ 3.11、[Claude Code](https://claude.com/claude-code)、[pandoc](https://pandoc.org)（`brew install pandoc`）。

```bash
git clone <本仓库>
cd OpenSocialScience

python3 -m venv .venv && source .venv/bin/activate
pip install -e ".[dev,figures,stats-formats,excel,causal,reading]"
pip install python-docx        # 可选：没有期刊模板时生成标准排版的 Word

oss install-skills             # 把 5 份 skill 铺到 ~/.claude/skills/
```

各 extras 是干什么的：

| extras | 不装会怎样 |
|---|---|
| `stats-formats` | 读不了 `.dta` / `.sav`，只能读 CSV / Excel |
| `figures` | 画不出图 |
| `causal` | 政策分批实施时用不了 `did_cs`（约 300 MB 依赖） |
| `reading` | 双栏 PDF 抽全文顺序会乱 |
| `excel` | 读不了 `.xlsx` |

## 二、配置

在项目根目录建 `.env`（照 `.env.example` 抄，**不要提交**）：

```bash
REVIEWER_BASE_URL=https://api.deepseek.com/v1   # 任何 OpenAI 兼容端点
REVIEWER_MODEL=deepseek-chat
REVIEWER_API_KEY=sk-...
EXECUTOR_MODEL=claude-opus-4                    # 宿主实际跑的模型

# 可选，配上通常能多拿三成全文
# UNPAYWALL_EMAIL=your@mail.com
# CORE_API_KEY=
# S2_API_KEY=
```

审稿模型最好跟执行模型**不是一家**。是一家也能跑，判词记成「自审」，不算独立验证，论文局限里要写一句。
要硬拦就在 `.env` 里加 `REQUIRE_CROSS_MODEL=1`，两边是一家直接不让跑。

然后自检：

```bash
oss doctor
```

全绿再往下走。有 `✗` 的照它给的命令补。

---

## 三、用

在项目根目录打开 Claude Code，输入一句话：

```
/social-research 教育扩张是否削弱了家庭背景对地位获得的影响 --- data: my_survey.dta --- discipline: sociology
```

它会自己跑到底（约 1–1.5 小时），产出在 `runs/<运行目录>/paper.docx`。

### 参数

用 ` --- ` 分段，顺序随意：

| 参数 | 必填 | 说明 |
|---|---|---|
| （第一段） | ✅ | 研究方向，一句话 |
| `data:` | ✅ | 数据文件路径，或数据包 `pack:qog`；多份用逗号隔开，可混用 |
| `discipline:` | | `economics`（缺省）/ `sociology` / `political-science` / `psychology` / `communication`。不同学科对「能不能说是因果」的要求不一样，这里决定审得多严、用哪些角度找题 |
| `lang:` | | `zh`（缺省，中文论文 + 中文期刊体例的图）/ `en`。**文献检索不受它影响**，中英文献都要 |
| `idea:` | | 你已经想好的题目，一段自由文本。给了它就**不再出题**，只把你这段整理成唯一候选，照样过陪审团和可行性检验；你的原话一字不改成为锚点，此后不许换题 |
| `design:` | | 你已经定好的计量设计，五个键：`outcome=` `treatment=` `fe=` `cluster=` `estimator=`，可以只给几个，没给的由它补 |
| `type:` | | `因果` / `描述` / `测量` / `仿真`。锁定研究类型，此后只许从因果降为描述，不许改大 |
| `refs:` | | 你自己的文献：题录文件、单篇 PDF，或整个 PDF 目录，逗号隔开（见下节） |
| `style:` | | 风格包名，`styles/<名>/` 要先存在 |
| `checkpoint:` | | `idea` / `ideas`（选完题停下来等你挑）/ `design`（因果审计判 FAIL 要换设计前停），逗号隔开；缺省都不停 |

`design:` 的五个键这样写，键名跟 `plan.json` 的字段不完全同名，系统会照表转换：

```
--- design: outcome=Risk, treatment=Misprice, fe=firm+year, cluster=firm, estimator=ols_fe
```

`estimator` 只认工具箱清单：`ols_fe` / `did` / `did_cs` / `event_study` / `iv` / `iptw` / `rdd` /
`describe` / `logit` / `ologit` / `mixed`。写了清单外的值它会停下来问你，不会猜一个近似的替上。

### 带自己的文献进来（中文研究基本都要走这一步）

知网、万方没有开放 API，自动检索够不到。两条路，可以混用：

| 你有什么 | 怎么给 | 它做什么 |
|---|---|---|
| 从知网 / 万方 / EndNote 导出的题录 | `--- refs: 导出文件.txt` | 认 **RIS**（`TY  - ` 开头）、**EndNote**（`%0`）、**RefWorks**（`RT`）、**NoteExpress**（`{Reference Type}:`）四种格式，直接并进文献语料 |
| 你下载好的 PDF | `--- refs: 某篇.pdf` 或 `--- refs: 我的文献/`（整个目录） | 有 DOI 的自动反查权威题录；没有的标 `[UNVERIFIED]` 交你确认。全文直接进精读目录，不用等开放获取 |

也可以在跑之前先手动导：

```bash
oss lit import <文件或目录> --run <运行目录>
```

导入的记录**没有 OpenAlex 编号，滚不了雪球**——检索与精读不受影响，但想顺着引文网络扩语料要手动。
另外，没读到全文的文献，论文里不许写「首次」，这是一道硬检查。

例子：

```
/social-research 互联网普及是否改变了民主化对民生的效果 --- data: pack:qog --- discipline: political-science --- style: social-forces --- checkpoint: ideas
/social-research 数字化对城乡收入不平等的影响 --- data: my.csv, pack:cgss --- discipline: economics
```

### 数据从哪来

```bash
oss data list                  # 有哪些现成数据包
oss data info qog              # 某个包的详情、引用格式
oss data get qog --run runs/xxx   # 下载到本地（qog / vdem / gss 直接下）
oss data search "internet"     # 按指标搜世界银行 / OECD / OWID
```

`cgss` / `cfps` / `wvs` 要自己注册申请，拿到后放进 `data/<名>/` 再 `get`。

### 按目标期刊写（可选）

**什么时候用**：你已经知道要投哪本刊。不用就跳过——系统会按标准论文格式写。

#### 第 1 步 · 建文件夹，放两样东西

文件夹名你定，之后就用这个名字。比如要投 Social Forces：

```bash
mkdir -p styles/social-forces/exemplars
```

**① 投稿须知** → `styles/social-forces/guide.md`

到期刊官网找「Instructions for Authors」或「Author Guidelines」那一页，**整页文字复制粘贴**进去。
不用整理格式，原文照抄就行——后面要拿它当原文核对，改写反而不好。

**② 范文** → `styles/social-forces/exemplars/`

该刊**近几年的研究论文 PDF，3–10 篇**。挑高被引的。

> 要的是 research article，**不要书评、不要评论、不要社论**——它们的结构不一样，会把骨架量歪。

**③ 出版社 Word 模板**（可选）→ `styles/social-forces/template.docx`

很多刊不提供，没有就算了。

放完长这样：

```
styles/social-forces/
  guide.md              ← 你复制的须知
  exemplars/
    soad063.pdf         ← 你下载的范文
    soad064.pdf
    ...
  template.docx         ← 可选
```

> 范文 PDF 不会进 git（`.gitignore` 里排除了），只在你本机用。

#### 第 2 步 · 建包

```bash
oss style build social-forces
```

它会把范文的 PDF 抽成文字，**量出这本刊的骨架**：

```
✓ style_profile.json  →  styles/social-forces/style_profile.json
  范文 6 篇，能用 6 篇；节顺序 ['abstract', 'introduction', 'background',
                              'data_methods', 'results', 'discussion', 'limitations']
  words_body             7039–10421（中位 9290.5）
  words_abstract         84–362（中位 164.0）
  n_tables               1–5（中位 2.5）
  n_figures              4–6（中位 5）
  cites_per_1000         5.6–11.6（中位 7.2）
  引用形式 author-year
```

**第一次跑，末尾多半会看到这一行：**

```
↳ 有 guide.md 但还没有 rules.json：读须知填一份，再跑一次 build 核对
```

这是正常的。`rules.json` 是把须知里的硬规矩变成数字（字数上限、图表上限、双盲、摘要能不能引用……），
**由模型读须知去填，不用你填**——你在 Claude Code 里跑 `/social-research ... --- style: social-forces` 时它会自己填好。

想自己填也行：`oss schema rules --example` 看格式。填完再跑一次 `build`，它会**逐个数字回到须知原文里核**——
找不到出处的数字会被拒绝（编一个字数上限跟编一个回归系数是一回事）。

建好之后再跑一次，末尾应该是：

```
✓ rules.json 每个数字都能在须知原文里找到
```

#### 第 3 步 · 用

在 `/social-research` 命令里加一段：

```
/social-research 你的研究方向 --- data: your.csv --- discipline: sociology --- style: social-forces
```

#### 它会影响什么

| 层 | 从哪来 | 具体做什么 |
|---|---|---|
| **结构** | 范文 | 按范文的多数派给出节顺序和各节目标词数，当起稿模板；成稿按同一骨架查 |
| **行文** | 范文 | 写作前先读范文的引言和讨论，写一份「这本刊怎么讲故事」的说明（`style_notes.md`） |
| **语言** | 范文 | 句长、引用密度、第一人称频率当目标，偏离只警告不拦 |
| **排版** | 须知 + 模板 | 字数、图表上限、双盲、摘要不引用等**硬规矩不合就不给导出**；参考文献按须知说的格式排；有模板套模板 |

> 🔒 **只学套路，不抄句子。**成稿跟任何一篇范文**连续 8 个词相同**就直接拒绝。

#### 单独查一份成稿

```bash
oss style check --run runs/xxx --style social-forces
```

#### 不给风格包会怎样

走标准骨架（Abstract / Introduction / Background / Data and Methods / Results / Discussion /
Conclusion / References），Chicago 作者-年份引用，Times New Roman 12 号双倍行距。**照样能出 Word。**

## 四、命令速查

平时不用手敲，skill 会自己调。要单独用时：所有命令都从**项目根目录**跑（不要 `cd` 进运行目录），都带同一个 `--run`（缺省 `runs/current`）。

```bash
oss doctor                                          # 自检
oss profile data.csv --run runs/xxx                 # 数据画像
oss merge a.csv b.csv --on country,year --run runs/xxx   # 拼数据（会摊开丢了什么）
oss power --run runs/xxx --effect 0.2               # 统计功效
oss run --run runs/xxx                              # 按 plan.json 跑分析
oss route --run runs/xxx                            # 诊断 → 开处方
oss review --paper --run runs/xxx                   # 叫别家模型审论文
oss paper check --run runs/xxx                      # 校验（不过就不给渲染）
oss paper render --run runs/xxx                     # 占位符填成真数字
oss paper export --run runs/xxx                     # 导出 Word
oss eval --run runs/xxx                             # 核这次跑有没有照说明书做
oss style build social-forces                       # 建风格包（量范文骨架、核须知）
oss style check --run runs/xxx --style social-forces  # 单独对着期刊规矩查成稿
oss schema plan                                     # 查某个产出物该长什么样
oss smoke                                           # 跑完整条链，检查产出物齐不齐
```

## 五、产出在哪

一次运行一个目录 `runs/<名>/`：

| 文件 | 是什么 |
|---|---|
| `paper.docx` | **交付物** |
| `paper_rendered.md` | 填好数字的稿 |
| `results.json` / `power.json` | 结果与诊断 / 功效报告 |
| `route.json` / `eval_report.json` | 处方与处置 / 说明书测试打分 |
| `review_*.json` | 各轮审稿意见 |
| `fig_*.png` / `fig_*.pdf` | 图 |
| `trace.jsonl` | 每一步留痕 |

## 六、常见问题

| 症状 | 怎么办 |
|---|---|
| `oss doctor` 说 skill 跟源头不一致 | `oss install-skills --force` |
| 导出 Word 失败 | 装 pandoc：`brew install pandoc` |
| `oss doctor` 说审稿是「自审」 | 审稿模型和 `EXECUTOR_MODEL` 是一家，或者 `EXECUTOR_MODEL` 没填。能跑，但不算独立验证，论文局限里要写一句 |
| 审稿这一步被拒绝执行 | 开了 `REQUIRE_CROSS_MODEL=1`，而两边是一家或认不出哪家。换个审稿模型，或者去掉那行 |
| 读不了 `.dta` / `.sav` | `pip install 'opensocialscience[stats-formats]'` |
| 报「政策分批实施但用了 TWFE」 | `pip install 'opensocialscience[causal]'` |
| 产出跑进了 `runs/xxx/runs/xxx/` | 命令里 `cd` 过了；所有命令都从项目根、用相对路径跑 |
| 跑一半停住问你 | 你加了 `checkpoint:`，或数据没给、要申请的数据包拿不到 |
| `style build` 说范文「能用 0 篇」 | PDF 抽不出文字（扫描件），换一份；或放的是书评不是研究论文 |
| `style build` 说 rules.json 里的数字在须知里找不到 | 那个数字是编的，回 `guide.md` 核对原文 |
| 导出被期刊硬规矩拦下 | 超字数或超图表上限了，按提示删；规矩来自你放的 `guide.md` |

---

## 七、它不做的

- 质性研究（民族志、深度访谈、扎根理论）
- LaTeX、海报、幻灯片——只出 Word
- 中文文献检索（知网、万方无开放 API），中文情境的「没人做过」是盲的
- 替你签数据使用协议
